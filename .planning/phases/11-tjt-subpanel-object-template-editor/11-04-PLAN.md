<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| typed/hex edit -> `.iff` bytes (save) | Edited bytes are written to a loose override or repacked `.tre` that a live SWG client later loads |
| save target selection -> filesystem / archive | Save-As / loose-override / repack write to disk; repack mutates a source archive |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-11 | Tampering | A typed widget commits an invalid value that corrupts a param chunk | mitigate | Typed widgets are type-constrained (numeric up-down, checkbox); complex/ambiguous params are read-only-inline and edited only via the hex sub-editor through MutableIffDocument; the round-trip golden (Plan 02) is the byte-exact regression lock |
| T-11-12 | Tampering / Repudiation | Repack overwrites a source `.tre` without backup or on a V6000 archive | mitigate | Forward to Phase 8 `TreRepackSaveTarget` which enforces the V6000 (WR-06) refusal, timestamped backup, repack lock, and atomic File.Replace — do not bypass; repack gated behind `FormSaveConfirmDialog` |
| T-11-13 | Spoofing / DoS | Over-promising "reflected on respawn" misleads the user into shipping a stale edit | mitigate | LOCKED CF-05 tier-(b) badge wording (respawn unreliable; relog guarantees), verified by the verbatim-string grep gate; editor STATES, never triggers a reload (CON-M-05) |
| T-11-14 | Tampering | Live-patch (mode 3) write to client memory enabled prematurely | mitigate | Mode 3 ships DISABLED with the inherited CF-03 tooltip; no in-memory write path is wired this phase |
| T-11-SC | Tampering | npm/pip/cargo installs | accept (N/A) | No packages installed this plan |
| — | S/R/I (auth/session/network) | — | accept (N/A) | Local WinForms editor + file/archive save; no auth/session/network surface |
