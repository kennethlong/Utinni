# Phase 11 — UI Design Contract: TJT Object Template Editor (`.iff`)

> Visual and interaction contract for the Wave-1 object-template editor: a **property-grid-style
> effective-inheritance view** over object-template `.iff` files (the SWG `ObjectTemplate`
> hierarchy that drives in-world object behaviour and appearance), rendered as a
> `ThemedDataGridView` of **one row per field** with columns **Field · Effective value · Origin ·
> Type**, an **ancestor breadcrumb** header (`shared_base_tangible → … → this`), SOE-parity
> mutation (edit a local override · promote an inherited field to a local override · revert a
> local override back to inherited — `D-04`), **typed widgets for scalars + a raw-hex fallback for
> complex param types** so no param is ever uneditable (`D-02`), generic across every
> object-template type with no schema port (`D-03`), graceful degradation on an unresolved base
> (never blocks the open — `D-01`), editor-local undo/redo, three save modes (loose-override /
> Save·Save-As / `.tre` repack; in-memory live-patch DISABLED inherited), and the locked CF-05
> tier-(b) reload-status badge. Three entry points (file picker + TRE Browser hand-off + IFF
> Editor "switch to typed view" hand-off — the last applies because object templates ARE IFF).
> Shipped inside The Jawa Toolbox (DEC-C4 / CF-06). **This is the fifth and final V1 SubPanel.**
> Generated by gsd-ui-researcher.
>
> **PLATFORM: .NET Framework WinForms desktop UI — NOT web/CSS.** No component library, no
> shadcn, no Tailwind, no icon font, no `components.json`. The "design system" is the existing
> Utinni themed WinForms control suite (`UtinniCoreDotNet.UI`) plus the Phase 9
> `ThemedDataGridView` wrapper. Every token below is **INHERITED** from the approved Phase 7/8/9/10
> UI-SPECs and verified against live code (`Colors.cs`, `FormDatatableEditor.cs`,
> `ObjectTemplateDecoder.cs`) — none invented in this phase.
>
> **THIS SPEC EXTENDS `07-UI-SPEC.md`, `08-UI-SPEC.md`, `09-UI-SPEC.md`, AND `10-UI-SPEC.md` — it
> does not re-derive them.** Phase 7's design system / spacing / typography / color contract /
> host-placement rule, Phase 8's Wave-1-editor patterns (dirty marker, Save▾ drop-down,
> `FormSaveConfirmDialog`, editor-local undo/redo, reload affordance, status strip), Phase 9's
> `ThemedDataGridView` token map + Find/Replace pane + view-only sort + cell-state overlays +
> per-type widget contract + IFF-Editor "switch to typed view" hand-off, and Phase 10's
> singleton-form + filter-row precedents are treated as LOCKED and inherited verbatim. The
> sections below restate the locked tokens for the checker's six dimensions, then specify ONLY the
> new/changed surfaces Phase 11 adds: **the effective-inheritance Field/Value/Origin/Type grid, the
> origin-marker rendering, the ancestor breadcrumb header, the promote/revert/edit triggers, the
> hex-fallback sub-editor surfacing, and the dirty-state placement.**

## Host Placement Decision

**DECISION: Ship the Object Template Editor as a NEW resizable `UtinniForm`
(`FormObjectTemplateEditor`), registered in TJT's `GetForms()` list — exactly per the Phase
7/8/9/10 precedent rule (DEC-C4 / CF-06).** It is a sibling of `FormDatatableEditor` /
`FormStringTableEditor`, not a subclass (a shared abstract editor base is the deferred post-Wave-1
refactor candidate noted since Phase 9). Because object templates ARE IFF, there IS an IFF Editor
hand-off ("Switch to typed object-template view" in `FormIffEditor`, mirroring Phase 9 D-10.3 —
contrast Phase 10's flat `.stf` which had none).

| Property | Value |
|----------|-------|
| Host type | `UtinniForm` (resizable, custom titlebar, `DrawName = true`, TJT icon — mirrors `FormDatatableEditor`) |
| Window title | `Object Template Editor` — with a leading `● ` dirty marker per Phase 8 idiom |
| Default size | 1200 × 760 (persist `[ObjectTemplateEditor] width/height` to settings.ini; matches the datatable default — a four-column property grid plus the breadcrumb header needs the datatable-class width) |
| Minimum size | 900 × 560 (below this the four columns + breadcrumb + toolbar + status badge are unusable) |
| Open behavior | "Already open? `Activate()` : `Show()`" + single-document-per-window with dirty-discard prompt (08-05 singleton-form-hide-not-dispose: on `CloseReason.UserClosing` cancel close + `Hide()` via `SingletonFormClosePolicy`) |
| Multi-document | V1 default: **single document per window** (open-replaces with a dirty-prompt). Tabbed/MDI deferred — same posture as Phases 8/9/10 |
| Settings persistence | `[ObjectTemplateEditor] width`, `height`, `findReplaceVisible`, `showInheritedRows` (the inherited-fields visibility toggle — see *Columns*), `looseOverrideDir` (mirrors Phase 8/9/10) |

**MEF SPI conformance (CON-M-01/02):** the new Form returns from `GetForms()`; the interface is
NOT widened (preserve STAB-04 foundations). `*Impl` separation per CON-T-05. Registered in TJT
`Plugin.cs` `SubPanelContainer`/`GetForms()` inside try/catch (Phase 8/9/10 precedent), as the
fifth and final V1 SubPanel.

**Fallback if the Form path is blocked in execution:** degrade to a `StandalonePanel` (dockable
UserControl) at no less than 1000×620; never the fixed 417px SubPanel. (Same fallback as Phases
7/8/9/10.)

### ThemedDataGridView token map (INHERITED from Phase 9 — restated, not re-derived)

Phase 11's grid is a `ThemedDataGridView` and inherits the **entire** Phase 9 token map verbatim
(`BackgroundColor = Colors.PrimaryHighlight()`, `GridColor = Colors.ControlBorder()`,
`BorderStyle.None`, `EnableHeadersVisualStyles = false`, column-header band `Colors.PrimaryShadow()`
bg / `Colors.Font()` fg, `DefaultCellStyle` `Colors.PrimaryHighlight()` bg / `Colors.Font()` fg,
selection `Colors.Secondary()` bg / `Colors.Font()` fg, alternating-row `Colors.Primary()` zebra,
`RowTemplate.Height = 22px`, `ColumnHeadersHeight = 24px`, `RowHeadersWidth = 40px`,
`CellBorderStyle = SingleHorizontal`, `AllowUserToAddRows = false`, `AllowUserToDeleteRows = false`,
`MultiSelect = true`, `SelectionMode = CellSelect`, `ScrollBars = Both`,
`Font = Microsoft Sans Serif 8.25pt`).

**Phase 11 DEVIATIONS from the Phase 9 token map (justified by the property-grid / fixed-column shape):**

| Property | Phase 9 value | Phase 11 value | Why |
|----------|---------------|----------------|-----|
| `AllowUserToOrderColumns` | `true` (gated by safety-net modal) | **`false`** | The column set is fixed (Field, Effective value, Origin, Type). There is no by-index runtime-consumer risk, and reordering the four meta-columns has no meaning. The Phase 9 column-reorder/delete safety-net modal is therefore **N/A** in Phase 11. |
| `AllowUserToResizeColumns` | `true` | `true` (unchanged) — but the **Field**, **Origin**, and **Type** columns are width-stable; only **Effective value** is `AutoSizeMode = Fill` | A param value (especially a hex-fallback raw value) can be long; the value column absorbs the width. |
| `MultiSelect` | `true` (block-select for cut/copy/paste) | **`false`** → single full-row select (`SelectionMode = FullRowSelect`) | The unit of action is a FIELD (promote/revert/edit a row's value), not a cell block. Full-row select makes the origin/promote/revert affordances unambiguous. (This is the natural property-grid selection model.) |

Origin cell `ForeColor = Colors.Secondary()` (accent) — local overrides are the editable, locally-owned rows. |
| **Inherited (origin)** | Field has no local chunk; effective value comes from an ancestor | Field + Effective-value + Type cells render `ForeColor = Colors.FontDisabled()` AND `Font` italic (the greyed/italic "inherited" cue, CONTEXT D-01); Origin cell text `inherited from {ancestorName}` at `Colors.FontDisabled()`. The row is still selectable + viewable; editing it promotes it (see States). |

## Columns (NEW — the core Phase 11 surface decision, the only "Claude's Discretion" lock)

The grid binds **four columns**, all read-only as columns (the user edits the *value* of a row, not
the meta-columns):

| Column | Header | Editable? | Widget | FillWeight | Notes |
|--------|--------|-----------|--------|-----------|-------|
| **Field** | `Field` | No (the field name is structural) | `DataGridViewTextBoxColumn`, `ReadOnly = true` | ~25% | The NUL-terminated param field name. Sortable (view-only). Inherited rows render dimmed/italic. |
| **Effective value** | `Effective value` | **Yes** (this is the one editable surface — typed widget OR hex-fallback) | per-type widget via `EditingControlShowing` (see *Per-type value widget contract*) OR read-only hex cell for complex types | ~50% (`AutoSizeMode = Fill`) | The resolved value (the value from the nearest ancestor — including this template — that has a local param chunk, replicating the verified `if(!isLoaded()) return base->getXxx()` semantics). Editing an inherited row's value PROMOTES it to a local override (D-04). |
| **Origin** | `Origin` | No | `DataGridViewTextBoxColumn`, `ReadOnly = true` | ~18% | `local override` (accent) / `inherited from {name}` (dimmed) / `unresolved base {name}` (red). The single most load-bearing column of this editor — it is what makes this an *object-template* editor rather than the IFF editor pointed at a template. |
| **Type** | `Type` | No | `DataGridViewTextBoxColumn`, `ReadOnly = true` | ~7% | The decoded param type label: `bool` / `int` / `float` / `string` / `stringId` / `template-ref` / `enum` / `vector` / `trigger-volume` / `raw bytes (hex)` / `(unknown)`. Drives which value widget is used. |

**The row set** = the union of every field that appears in a local param chunk anywhere in the
resolved DERV chain (this template + each resolvable ancestor), one row per distinct field, with
the effective value resolved to the nearest-ancestor-with-the-chunk. This is the D-01
effective-merged view. Fields that exist ONLY in an unresolved base are not invented; their absence
degrades gracefully (the open never blocks).

**`Show inherited` toggle:** a toolbar `UtinniToggleButton` labeled `Show inherited` (default ON;
tooltip when OFF: `Showing local overrides only. Toggle to show inherited fields.`). Persists
per-editor-instance via `[ObjectTemplateEditor] showInheritedRows`. Default ON — the full SOE
property-grid mental model.

**Machine-managed, NEVER surfaced as editable (CONTEXT D-04 locked floor):** the version-form
param-count chunk, the per-param `@derived`/loaded flags, and the param wrapper framing
(data-type tag, delta byte, weighted-list/range framing) are maintained by the writer and are
NEVER user-editable cells. The user edits field VALUES and override membership (promote/revert)
only. There is no column or cell for the count chunk or the flags.

### Breadcrumb header (NEW — D-01)

A `Panel pnlBreadcrumb` (`Dock = Top`, `Height = 24px`, background `Colors.Primary()`) sits BELOW
the toolbar and ABOVE the Find/Replace pane, holding one `UtinniLabel lblBreadcrumb`
(`Dock = Fill`, `AutoEllipsis = true`, `Colors.Font()`):

- Content: the resolved ancestor chain from root to this template, e.g.
  `shared_base_tangible → shared_tangible → shared_weapon → this`.
- The terminal `this` segment renders at `Colors.Secondary()` (accent) to mark the open document;
  the rest render at `Colors.Font()`; an **unresolved** ancestor segment renders at `Color.Red`
  with a trailing `(unresolved)` (e.g. `shared_missing → (unresolved) → this`).
- Read-only context in V1 (NOT clickable navigation — change-base / cross-template navigation is
  V2). When there is no base (the template declares no DERV), the breadcrumb reads just `this`.
- A leading short label `Inherits:` precedes the chain at `Colors.FontDisabled()`.

### Per-type value widget contract (NEW — derived from CONTEXT D-02 + RESEARCH self-describing decode)

The Effective-value cell's editor is chosen by the decoded param Type. Typed widgets cover the
scalar set; everything else falls to the hex sub-editor. **Guarantee: no param type is ever
uneditable.** Editing an inherited row's value PROMOTES it to a local override on commit (D-04).

| Decoded Type | Value widget | Notes |
|--------------|-------------|-------|
| `bool` | `DataGridViewCheckBoxColumn` (cell swap) | SINGLE bool; no delta byte |
| `int` | `UtinniNumericUpDown` via `EditingControlShowing` (Phase 9 swap), `DecimalPlaces = 0` | SINGLE int. RANGE/DIE_ROLL int forms render read-only summary text (`min..max` / `{n}d{s}+{b}`) with an `Edit…` affordance routing to the hex sub-editor in V1 (range/roll typed widgets are V2) |
| `float` | `UtinniNumericUpDown`, `DecimalPlaces = 6` (planner may tune) | SINGLE float; RANGE renders `min..max` read-only with `Edit…` → hex sub-editor (V2 typed range) |

| `stringId` | `DataGridViewTextBoxColumn` rendering `{table}:{index}`, edited via a small inline two-field form OR (planner discretion) the hex sub-editor | nested StringParam table + index |
| `template-ref` | `DataGridViewTextBoxColumn` (free text path) + an optional `⋯` picker affordance (file picker scoped to template `.iff`) | a struct-tagged template reference; if the on-disk shape is a full `StructParamOT`, route to hex sub-editor |
| `enum` | `DataGridViewTextBoxColumn` showing the raw enum VALUE (no friendly names — D-03 defers the schema that maps value→label to V2) | value-only; friendly enum dropdowns are V2 |
| `vector` | read-only summary (`x, y, z` / `x, z` when ignoreY) + `Edit…` → hex sub-editor in V1 | nested FloatParams; typed vector widget is V2 |
| `trigger-volume` | read-only summary (`{name} r={radius}`) + `Edit…` → hex sub-editor | nested StringParam + FloatParam |
| `raw bytes (hex)` | read-only `Consolas 9pt` hex cell + `⋯` → Phase 8 hex/text leaf sub-editor | struct / weighted-list / dynamic-variable params, OR any param whose generic scalar decode did not consume the chunk exactly (defensive fallback) |
| `(unknown)` (unresolved-base-only field) | not editable | shows `(unresolved)` at `Color.Red`; cannot promote a value we never resolved |

**Defensive decode posture (RESEARCH-locked):** the generic decoder attempts the scalar decode for
the leading data-type tag; if the decoded value does not consume EXACTLY the chunk payload bytes,
the param is treated as `raw bytes (hex)` rather than guessed. This preserves byte-exactness — the
hex fallback edits the raw leaf via `MutableIffDocument`.

    live-scene objects).
  - `Ctrl+S` → default Save (Save-in-place when `Source is LooseFile`, else Save As — inherited).
  - `Ctrl+F` → toggle Find pane, focus `txtFind`.
  - `Ctrl+H` → toggle Replace pane, focus `txtFind`.
  - `Esc` (while a Find/Replace input is focused) → collapse the pane.
  - `F3` / `Shift+F3` → Find next / previous when the Find pane is open.
  - Promote / Revert have no default chord in V1 (toolbar buttons + context menu only); planner MAY
    add `Ctrl+Shift+P` / `Ctrl+Shift+R` if non-colliding.
  - Native `DataGridView` keys (arrows, Tab, Enter, F2 edit) preserved.
  - Tab order: toolbar → breadcrumb (skip — read-only label) → Find pane (if visible) → grid →
    status strip.
- **Inherited vs local is glyph/style + color, not color-alone:** inherited rows use BOTH italic
  font style AND `Colors.FontDisabled()`; local overrides use BOTH the `local override` Origin TEXT
  AND accent; unresolved uses the `unresolved base {name}` TEXT AND red. State is legible without
  relying on color discrimination alone (inherits Phase 8 dual-coding principle).
- **Dirty-glyph + color, not glyph-alone:** dirty / promoted cells use BOTH a row-header text glyph
  (`●`) and the accent color; reverted rows use `↩` (Phase 8 idiom).
- **Thread marshaling (CON foundations):** file open / parse / DERV-chain resolution / save all run
  on a background `Task`; every UI mutation marshals via `Control.Invoke` / `BeginInvoke`. The
  (disabled) live-patch path and any client-memory touch run on the game thread via
  `GameCallbacks.AddMainLoopCall` per CON-N-04.
- **No modal blocking for progress:** loading / resolving / saving are inline status-strip text,
  never modal spinners. Modals are reserved for the revert-confirm + the inherited risk
  confirmations + the hex-fallback sub-editor.
- **Edits never silently lost:** a failed save RETAINS dirty state; closing/opening while dirty
  always routes through the discard-confirm modal (Phase 8 idiom).
- **Unresolved base NEVER blocks the open (D-01 LOCKED):** an unresolved ancestor degrades to the
  red origin cue + informational status; local params stay fully editable; no exception, no blocked
  open.
- **High-DPI:** inherit `AutoScaleMode.Font` from `UtinniForm`; no hard-coded pixel sizes beyond the
  documented control metrics.
- **Singleton-form hide-not-dispose (LOCKED, inherited; verified live in `FormDatatableEditor` via
  `SingletonFormClosePolicy.ShouldHideInsteadOfDispose`):** on `CloseReason.UserClosing`, cancel
  close + `Hide()` instead of disposing; host-shutdown reasons fall through normally.

## Decisions That May Need User Input (kept tight — most is locked by 11-CONTEXT.md)

Recorded as **assumptions with a sensible default**; the orchestrator/planner should confirm or
override. None blocks the spec.

1. **Default `Show inherited` = ON.** The full SOE property-grid mental model shows every effective
   field with its origin; the toggle lets a user collapse to local-overrides-only. *(CONTEXT left
   the exact surfacing to this UI-phase; the locked floor is "inherited fields are viewable with
   visible origin," which ON honors. Alternative: default OFF for a leaner local-only view — not
   recommended; it hides the editor's distinguishing feature.)*
2. **Promote/revert are toolbar buttons + a row context menu, with edit-an-inherited-row also
   promoting on commit.** Rationale: three discoverable affordances for one mutation family;
   editing-promotes matches the SOE "just set the value" muscle memory. *(CONTEXT delegated the
   trigger choice; the locked floor is "override/revert operations exist." Planner may add the
   `Ctrl+Shift+P/R` chords.)*
3. **The hex-fallback sub-editor is a per-call MODAL (`FormParamHexEditor`) wrapping the Phase 8 IFF
   leaf editor**, not a docked pane. Rationale: keeps the property grid lean and reuses the proven
   Phase 8 hex/text/replace-from-file surface verbatim. *(CONTEXT delegated "how the hex-fallback
   sub-editor is surfaced.")*
4. **Origin column is dedicated (column 3), not folded into the value cell.** Rationale: a separate
   sortable Origin column makes "show me all my local overrides" a one-click sort and keeps the
   value cell clean for the editor widget. *(CONTEXT delegated column layout; the locked floor is
   "visible origin.")*
5. **Breadcrumb is read-only context in V1, not clickable navigation.** Rationale: navigating to /
   opening an ancestor (and change-base re-parenting) is explicitly V2; a read-only chain satisfies
   the D-01 "ancestor breadcrumb shown as header" floor without scope creep.
6. **Delta-numeric params get a typed widget showing the delta form IF the delta byte round-trips
   verbatim; otherwise hex fallback.** Default: typed with the delta tooltip. Planner may route all
   delta params to hex if the edit UX is unclear (RESEARCH §MUST-CONFIRM #3 subtlety). Either keeps
   byte-exactness.

These do not change locked decisions; flag any disagreement at planning time.
