<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local process → named pipe (in-client server) | Any local process that knows the pipe name can connect; the server runs inside the injected x86 client |
| pipe worker thread → game thread | Reload work must cross from the background worker onto the game thread only via the marshal queue |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-10 | Spoofing/Elevation | Unauthorized local process connects to the pipe and triggers reloads | mitigate | PipeSecurity/PipeAccessRule restricts the pipe to the current user; NamedPipeServerStream is local-machine only (no network). Acceptance: server constructs the pipe with a current-user ACL. |
| T-16-11 | Tampering (integrity) | Reload work executed on the wrong thread → client AV/crash | mitigate | All reload work marshals via GameCallbacks.AddMainLoopCall; the worker thread never dereferences game state (Pitfall 2). Acceptance: the accept/decision path has no direct game-state access; only one Action crosses. |
| T-16-12 | DoS | Malformed/oversize wire frame on the in-client server thread | mitigate | Bounded max envelope size + op allow-list ({ping,reload-asset}); a bad frame closes that connection only, never the game thread. Acceptance: oversize-frame-rejection test. |
| T-16-13 | Spoofing | Pipe name collision / squatting (another process pre-creates the pipe) | accept | Sufficiently-specific pipe name; server owns creation (NamedPipeServerStream). Single-user local desktop trust assumption (analog AR-14-03/04). |
| T-16-SC | Tampering | npm/pip/cargo installs | n/a | No new packages this phase — BCL System.IO.Pipes + System.Text.Json only; Package Legitimacy Gate not triggered (RESEARCH §Package Legitimacy Audit). |
</threat_model>
