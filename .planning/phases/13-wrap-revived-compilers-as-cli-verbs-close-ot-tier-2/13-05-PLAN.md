<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller path -> exporter -> internal system()/popen() | The exporters shell out (`system("TemplateCompiler "+path)`) — the inherited SOE injection surface; the wrapper is the control point. |
| caller path -> DataTableTool / TemplateDefinitionCompiler process | Process.Start of a native exe with a caller-supplied path. |
| tools.cfg fixture -> exporter config | The exporter reads config keys from a staged tools.cfg. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-03 | Tampering/EoP | exporter internal `system("TemplateCompiler "+path)` | mitigate | THE tracked command-injection threat. The wrapper VALIDATES the input path (reject shell-meta / `..`) BEFORE invoking the exporter (Task 3); the exporter's own system() is never fed an unsanitized caller string. ASVS V5. |
| T-13-13 | Tampering/EoP | NativeToolRunner Process.Start (compile-definition/compile-datatable) | mitigate | UseShellExecute=false + arg array (inherited from the 13-02 seam) — the wrapper never shell-concatenates. |
| T-13-14 | Information disclosure | __DATE__/abs-path in generated schema/.cpp/.iff | mitigate | NormalizeBanner before committing schema + goldens (Pitfall 3) — TemplateDefinitionCompiler embeds date/abs-path in generated output. |
| T-13-15 | Spoofing | staged TemplateCompiler.exe resolution for the exporter chain | mitigate | Stage the exporter, tools.cfg, and TemplateCompiler.exe in one controlled dir; set WorkingDirectory explicitly — never rely on ambient PATH (Pitfall 2). |
</threat_model>
