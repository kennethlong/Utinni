<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| exe export → resolver | The `GetEngineHookPoints` table is produced by the user's own swg-client-v2 build — trusted source, but a partial/malformed/absent table must degrade gracefully (robustness, not adversarial defense). |
| resolver → swg::* literals | The resolver mutates in-process function-pointer slots before detours install; a wrong bind would corrupt a detour target. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-01 | Denial (crash) | resolve() table parse | mitigate | Null-check `pGet`, `table`, `table->entries`, `count`, and each `addr` before binding; `[endpoints][robustness]` unit asserts no deref on null/partial/zero-count/null-addr (mirrors `directx11.cpp` `tryInstall` null-checks). |
| T-24-02 | Tampering (version drift) | version field | mitigate | Version mismatch logs a soft warning and resolves by name; `[endpoints][version]` covers version=999. The real drift gate is the byte-identical `.inc` (Task 1) + the X-macro subset static_assert (Task 2). |
| T-24-03 | Spoofing (wrong path) | dual-path selection | mitigate | Export-absent → strict no-op; `[endpoints][dualpath]` asserts zero slot mutation so the SWGEmu RVA path is byte-for-byte unchanged (D-00 / criterion 3). |
| T-24-04 | Tampering (binding drift) | s_bindings[] vs .inc | mitigate | Compile-time X-macro subset `static_assert` fails the BUILD if a binding name is not in the `.inc` (EPA-04). |
| T-24-SC | Tampering | npm/pip/cargo installs | mitigate | Not applicable — this phase installs ZERO external packages (all machinery is in-repo C++). No package-legitimacy checkpoint required. |

No HIGH-severity threats: offline single-user local modding tool, no network surface, no untrusted input.
</threat_model>
