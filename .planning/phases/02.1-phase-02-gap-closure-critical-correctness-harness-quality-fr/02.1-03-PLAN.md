Problem: `GCHandle.Pinned` returns a pointer into the managed heap (GC heap). Passing this to `utinni_test_freeConfigBuffer` which is a no-op means we're testing nothing. The correct scenario is:
- Allocate from the OS heap (HeapAlloc via Marshal.AllocHGlobal) — this is from a DIFFERENT heap than any CRT's `free()`
- Pass to the export
- Assert no crash
- Free via Marshal.FreeHGlobal (correct owner)

If `delete[]` were re-introduced in the C++ export (the CR-02 regression scenario):
- The export receives an OS-heap pointer
- `delete[]` calls the CRT's `_free_dbg` or `free()` on it
- CRT heap != OS heap → `_ASSERTE(_BLOCK_TYPE_IS_VALID(pHead->nBlockUse))` fires in Debug, heap corruption in Release
- This WOULD crash or AV, and the test's `Record.Exception` would catch it

Target state for ConfigBufferFreeTests.cs:
