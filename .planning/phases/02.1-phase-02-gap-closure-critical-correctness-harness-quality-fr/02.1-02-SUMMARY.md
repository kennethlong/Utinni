## Accomplishments

### Task 1: CR-04/WR-03 — eager init functions in directx9.cpp/h + cleanup UAF fix (commit `408ca22`)

- **CR-04 startup fix:** `directX::initPresentBlockedEvent()` added to `directx9.cpp`. Calls `CreateEvent(nullptr, TRUE, FALSE, nullptr)` once. Declared in `directx9.h`.

- **CR-04 pure reader:** `getPresentBlockedEvent()` export simplified to `return hPresentBlockedEvent;`. The lazy `if (!hPresentBlockedEvent) { CreateEvent(...); }` block is removed. `CreateEvent` now appears exactly once in `directx9.cpp` (inside `initPresentBlockedEvent`).

- **WR-03 startup fix:** `directX::initDepthTexture()` added inside `namespace directX` block in `directx9.cpp`. Calls `depthTexture = new DepthTexture()`. Declared in `directx9.h`. DepthTexture ctor is D3D9-free (calls `NvAPI_Initialize()` only — verified in Phase 02.1 RESEARCH §WR-03).

- **WR-03 hkPresent defensive fallback:** `if (depthTexture == nullptr)` null-branch retained but now adds `utinni::log::critical(...)` regression warning. Branch is unreachable in production after eager init; log::critical ensures any regression is immediately visible.

- **WR-03 exit-UAF fix (critical guidance §1):** `directX::cleanup()` now contains ONLY a threading contract comment. The `delete depthTexture` and `depthTexture = nullptr` are intentionally omitted. Root cause confirmed live 2026-05-18: injected SWG exit fires "Direct3D could not be correctly initialized" dialog due to DLL_PROCESS_DETACH thread deleting depthTexture while render thread is mid-frame. Conventional Win32 DllMain teardown pattern: skip cleanup, let OS reclaim. Bounded "leak" (process lifetime) preferable to UAF.

- **CON-N-01 preserved:** 8 actual `Detour::Create(...)` calls in directx9.cpp — unchanged. Two new comment lines mention `Detour::Create` but contain no real calls.

- **CppSharp regenerated:** Post-build step regenerated `UtinniCoreDotNet/Generated/UtinniCore.cs` with `initPresentBlockedEvent` and `initDepthTexture` bindings.

### Auto-applied per critical_executor_guidance (not plan deviations — mandatory changes)

**1. [Critical Guidance §1] Dropped delete depthTexture in directX::cleanup()**
- **Why:** Exit-side UAF confirmed live 2026-05-18 (D3D9 dialog on SWG exit in injected sessions). Plan original action said "add threading contract comment before delete depthTexture". Guidance upgrades this to: drop the delete entirely.
- **Fix:** cleanup() contains ONLY the threading contract comment. OS reclaims heap on process exit. Bounded leak preferable to UAF.
- **Files:** `UtinniCore/swg/graphics/directx9.cpp`

- **Why:** Plan's proposed tests (`Assert.True(result == 0UL || result != 0UL)`) were Boolean tautologies. Plan-check Concern B flagged this as violating D-04.
- **Fix:** Added 4 new exports (`utinni_test_initPresentBlockedEvent`, `utinni_test_initDepthTexture`, `utinni_test_getPresentBlockedEvent`, `utinni_test_getDepthTexturePtr`). New tests call init export + assert non-zero + verify getter returns same value. Regression is detectable.
