## Implementation Decisions

### Plan Structuring (3 plans by theme, not by file)

- **D-01:** Plans grouped by **theme/risk-class**, not by file. Native correctness (CR-02/03 + WR-09), race hardening (CR-04 + WR-03), harness uplift (WR-01/02/05). Themes share dispositional decisions (e.g., the type-widening question for CR-02 informs the harness shape for WR-02).
- **D-02:** CI gate on every plan boundary — same `windows-2022` workflow as Phase 02. CR-02 requires SWG behavior investigation (disassembly at `0xAA4900`); partial-proof harness OK if full proof requires live SWG (Tier-4 residual, same boundary as Phase 02 D-06).
- **D-03:** Each finding fix lands as its own atomic commit. Roughly 8 fix commits (one per finding) plus harness/test commits.

### Verification Contract

- **D-04:** **Max-harness posture preserved from Phase 02 D-05.** Every finding closed in Phase 02.1 gets a regression test that would fail if the fix were reverted. Per-finding harness shape:
  - **CR-02 (`Network::cast` width):** function-pointer test double registered for `swg::network::cast`, writes a 64-bit sentinel through the OUT param; harness asserts the full 64-bit value round-trips. Catches "OUT param declared too narrow" via stack corruption check.
  - **CR-03 (UB shift):** static-analysis assertion via `-Wshift-count-overflow` (already a default MSVC C4293 warning) OR a unit test that calls `Network::cast` with `int.MaxValue` and asserts no spurious high half. Whichever the planner picks.
  - **CR-04 (`hPresentBlockedEvent` race):** can't reproduce the TOCTOU race deterministically from a unit test, but **eager-init in `utinni_init`** eliminates the lazy path entirely — assert `getPresentBlockedEvent()` returns the same HANDLE across 1000 concurrent calls (sufficient for "no double-create") AND `hPresentBlockedEvent` is non-null on entry to `hkPresent`.
  - **WR-03 (`depthTexture` race):** same eager-init pattern in `utinni_init` (or first frame of `hkPresent` with `InterlockedCompareExchangePointer`). Document threading contract for `directX::cleanup()` (must run after render thread quiesced).
  - **WR-01 (real C-03 harness):** replace `utinni_test_networkCast` with a wrapper that swaps `swg::network::cast` to a controlled test double via function-pointer reseat, calls `Network::cast(id)`, asserts the test double saw the right OUT param + `Network::cast` returned the right value. Removes the hardcoded `0xDEADBEEF` sentinel.
  - **WR-02 (real C-02 harness):** build a separate `Utinni.CrossCrtFreeFixture.dll` with its own CRT linkage (`/MD` vs UtinniCore's `/MT`, or vice versa); fixture allocates a buffer with `new[]` in its own CRT and exposes a `getBuffer()` export; xUnit P/Invokes both, hands the buffer to `utinni_test_freeConfigBuffer`, asserts no crash from the (now-removed) cross-CRT `delete[]`.
  - **WR-05 (affirmative `getVtbl`):** add a sibling test that does `LoadLibrary("d3d9.dll")` from the test, then calls `Utinni_GetVtbl()`, asserts non-zero. Pairs with the existing null-path test.
  - **WR-09 (`CoUninitialize` pairing):** unit test that calls a test export wrapping `utinni_init`'s COM bring-up + teardown, asserts no apartment leak via `CoGetApartmentType` query. Or simpler: drop `CoInitializeEx` entirely if no apartment-threaded COM consumer in `utinni_init` needs it (CLR Host is free-threaded).
- **D-05:** **Tier-4 residual after harness coverage:** none beyond what Phase 02 D-06 already established. CR-02 stack-stomp detection without a live SWG call is hard but the type-widening fix is statically verifiable (compiler-checked typedef + OUT param width). No new Tier-4 items introduced.

### CR-02 / CR-03 Disposition (SWG ABI Investigation)

- **D-06:** **Planner must investigate the actual SWG `Network::cast` ABI during Plan 02.1-01's research substep.** Three candidate dispositions:
  - **(a)** SWG `Network::cast` writes 8 bytes through `&networkId` (NetworkId is 64-bit, OUT param). Fix: widen typedef to `int64_t(__thiscall*)(int64_t*, int, int)`, widen `networkId` local to `int64_t`. Drop the `(id >> 32)` shift entirely (high half is always 0 since `int id` is 32-bit). Closes CR-02 + CR-03.
  - **(b)** SWG `Network::cast` writes only 4 bytes (NetworkId is 32-bit in this client build). Fix: keep `swgptr` typedef, drop CR-02 entirely (false alarm), still drop the `(id >> 32)` shift for CR-03. Add a `static_assert(sizeof(swgptr) == sizeof(int))` near the typedef.
  - **(c)** Hybrid: widen the OUT param to be safe but keep the return signed `int64_t` for ABI compatibility. Defensive. Reviewer-friendly.
  - Planner reads the SWG disassembly at RVA `0xAA4900` (via the existing test fixture `bin/Release/SwgClient_r.exe` once the user's local SWGEmu Core3 setup is online) AND audits the assessment.md TD-03 note. **Default if research inconclusive: option (c) hybrid.**
- **D-07:** **CR-03 disposition is gated by D-06.** If (a) or (c), the shift is dropped. If (b), the shift is still dropped (UB regardless of return type).

### CR-04 / WR-03 Disposition (Eager vs Interlocked)

- **D-08:** **Prefer eager init in `utinni_init` over `InterlockedCompareExchangePointer`.** `utinni_init` already runs on the launcher-spawned thread before any detour fires (it builds the detour table). Calling `CreateEvent` there once eliminates the lazy path. Apply same pattern to `depthTexture` — either eager-init in `utinni_init` if it's safe to construct without a live D3D9 device, or `InterlockedCompareExchangePointer` in `hkPresent` if not. Planner audits `DepthTexture::DepthTexture()` body to decide.

### WR-01 / WR-02 Disposition (Real Harness vs Mark as Tier-4)

- **D-09:** **Build real harnesses, do not mark as Tier-4.** This is non-negotiable per `feedback_max_harness` memory — the user's strong preference is "default to inventing a harness over manual smoke". The WR-01 test-double-via-function-pointer pattern is well-established (the C++ code already has `swg::network::cast` as a function pointer — just reseat it during the test). WR-02 cross-CRT fixture is more work but isn't unreasonable (a 40-line helper DLL).
