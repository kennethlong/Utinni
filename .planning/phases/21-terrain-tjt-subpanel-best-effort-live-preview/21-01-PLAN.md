<objective>
Lay the Wave-0 foundation every later plan in this phase depends on: a single testable source of
truth for the reload-tier candor copy (honoring the D-07 PendingNextSceneChange default), the in-proc
terrain edit-save target (mirror of IffSaveTargets, consuming the Phase 20 codec with ZERO new format
logic), the net-new LAYR-FORM→IHDR-leaf stable-id resolver the active-flag toggle needs, and the
Wave-0 automated test gaps the VALIDATION strategy mandates (including BOTH save paths' byte-parity).

Purpose: The candor copy lives in the UtinniPlugins UI, which `UtinniCoreDotNet.Tests` cannot reference
(it P/Invokes `Game.IsRunning`). The only way to automate the locked-copy assertion (a hard Wave-0 gap)
is to extract the tier→copy map into a pure framework-side helper both the UI and the test consume. This
plan also settles the in-proc-save decision and proves byte-parity against the shipped CLI before any UI
is built on top of it — for BOTH the typed-field path AND the IHDR active-flag path (RESEARCH Open
Question 2). The consumed model only exposes `TerrainLayer.StableIdPath` (the LAYR FORM path), NOT the
IHDR DATA leaf id that `--field active` mutates, and the CLI's `FindMutableLeafByStableId` walk is
PRIVATE to `ApplySaveTrnCommand` — so this plan adds the missing public bridge.

Output: `TerrainReloadCandor` helper + its test, an explicit `.trn → ReloadedTerrain` classifier
assertion, the in-proc `TerrainSaveTargets` save target with a net-new public IHDR-leaf-id resolver,
and a byte-parity test covering both the typed-field and active-flag edits against `apply-save-trn`.
</objective>

- **Save mechanism = in-proc** (`TerrainSaveTargets`, mirror `IffSaveTargets`), NOT a CLI shell-out of
  `apply-save-trn`. Rationale: in-proc is the established TJT save idiom; it avoids a process re-launch +
  re-parse; the byte-parity test in this plan guarantees it matches the CLI output exactly. (RESEARCH
  Alternatives / Discretion explicitly allow either; this plan picks in-proc and proves parity.)

  selected `TerrainLayer.StableIdPath` to the leaf the active-flag write demands. Plan 02 consumes it.
