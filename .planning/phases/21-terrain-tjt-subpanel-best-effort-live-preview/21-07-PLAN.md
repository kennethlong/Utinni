<objective>
Close R3: `FormTreBrowser.FindTerrainSubPanel()` walks `SubPanelContainer -> CollapsiblePanel -> SubPanel`
via a recursive `Controls` scan, but `CollapsiblePanel` realizes its `SubPanel` child lazily — it only calls
`Controls.Add(subPanel)` when the section is EXPANDED (`btnExpand_CheckedChanged` with `Open == true`). On a
fresh session the Terrain section is collapsed by default, so the SubPanel is NOT in the control tree and the
walk returns null → "Open in Terrain Editor" reports "Terrain Editor is unavailable in this session." The
workaround in the 21-04 smoke was to expand the section first.

Purpose: make the hand-off resolve the docked TerrainSubPanel regardless of expand state, without altering the
lazy-realize layout behavior every docked SubPanel relies on. The SubPanel instance already exists — it is held
in `CollapsiblePanel`'s private `subPanel` field from construction (Plugin.cs constructs all SubPanels eagerly
in the panels array literal); only the lazy Controls realization hides it from the recursive walk.

Output: a public read-only `WrappedSubPanel` accessor on the shared `CollapsiblePanel`, a `FindTerrainSubPanel`
that consults it (expand-state independent), and a framework-side regression proving the wrapped panel is
reachable while collapsed.
</objective>
