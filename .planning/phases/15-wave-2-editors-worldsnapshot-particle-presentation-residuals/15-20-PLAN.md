<objective>
Close 15-SMOKE Checklist **D-ii** (live-confirmed defect 2026-06-13): saving an `.stf` opened via the raw
`Open…` file dialog writes its loose override **flat** (`loose\ui_auc.stf`) instead of preserving the
logical subpath the client resolves by (`loose\string\en\ui_auc.stf`). Root cause:
`FormStringTableEditor.OnOpenClicked` (`FormStringTableEditor.cs:341`) passes `Path.GetFileName(path)` as the
logical name — the filename only — because a raw `Open…` dialog yields only an absolute filesystem path, not
the logical/TRE path. The `.prt` (B7) preserved its subpath ONLY because it was opened from inside the loose
tree (`loose\appearance\…`); the TRE-Browser "Open in …" hand-off carries the logical path, the raw dialog
does not. This is the Phase-8 Open Q2 *loose-override-subdir* gap, now concretely reproduced.

Purpose: RESID-03 (and every editor's loose-override save tier) depends on the loose override landing where
the client resolves it. A flattened override is silently never picked up — even once the loose searchPath is
re-enabled. The fix is a pure, unit-tested logical-path derivation applied at every raw-dialog open site.

Output: a BCL-only `LogicalAssetPath` helper in `UtinniCoreDotNet.PathContainment` (same single-source,
unit-testable placement as `LooseOverridePath`), wired into the editors' raw-`Open…` paths so the
loose-override `relAssetPath` carries the full logical subpath, with a safe filename fallback when the file
is outside the client root.
</objective>
