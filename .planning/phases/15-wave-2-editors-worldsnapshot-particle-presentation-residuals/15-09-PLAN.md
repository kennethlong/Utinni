<objective>
Close the BLOCKING crash gap (GAP 1.1 from 15-SMOKE.md Checklist A9): editor Undo of any WorldSnapshot bulk op null-derefs and takes down the SWG client (`0xC0000005` READ target=0x0 at a managed/JIT address). Root cause is confirmed in code: `WorldSnapshotNodePositionChangedCommand.SetPosition()` (`UtinniCoreDotNet/Commands/WorldSnapshotCommands.cs:140-141`) does `var obj = Network.GetObjectById(nodeCopy.Id); obj.Transform.Position = position;` with NO null guard, AND the `node` lookup (L143-151) is resolved AFTER the first `obj` deref and is itself dereferenced unguarded at L153 (`node.Transform.Position`). When the in-world object for that node id is not currently instantiated, `Network.GetObjectById` returns null → null-deref AV; independently, `GetNodeById`/`GetChildById` can return a null `node`. The Add / Remove / Rotation command bodies have the same unguarded `WorldSnapshotReaderWriter` / object lookups (`LastNode`, `ParentNode.LastChild`, `GetNodeById`, `obj.Transform.CopyRotation`).

Purpose: Undo is a core advertised bulk-op affordance (Checklist A9); a crash here is a hard blocker on PROD-W2-WS sign-off. Per the user's max-harness directive, the bail-on-null decision is extracted into a pure helper so the crash class gets unit coverage (the native `Network`/`WorldSnapshotReaderWriter` bridge is static-CppSharp and not loadable in the xUnit host, so the *decision* — not the native call — is what we test).

Output: All four WS `IUndoCommand` Execute AND Undo bodies bail gracefully on a null object/node lookup; a pure `WorldSnapshotCommandGuard` helper carries the decision and is unit-tested.
</objective>
