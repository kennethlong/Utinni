<objective>
Close the HEADLINE BLOCKING gap (15-SMOKE Checklist B5): under injection a loose-override Save from EVERY editor fails with `Could not load file or assembly 'UtinniCoreDotNet.PathContainment, Version=1.0.0.0 …'`. `UtinniCoreDotNet.PathContainment` is a netstandard2.0 assembly (it owns `LooseOverridePath` since Phase-14's `TypeForwardedTo` rework). `PathContainment.dll` IS deployed to `bin/Release`, but `netstandard.dll` — the façade a netstandard2.0 assembly needs to load inside a .NET-Framework host — is NOT, and the default AppDomain's APPBASE under injection is the SWGEmu.exe directory (not the Utinni inject root), so the BCL probe never finds it. The bug was never caught because CLI/MCP saves run in a net472 process where the façade resolves natively.

Purpose: this is cross-editor (it breaks the loose-override save tier for IFF/Datatable/Stringtable/ObjectTemplate/WorldSnapshot/Particle) and also blocks Checklist D's `.stf`/`.ot` saves (RESID-03). Without it, B5–B8 and Checklist D cannot pass the live re-smoke.

Output: an `AppDomain.AssemblyResolve` handler installed at `Startup.EntryPoint` that probes the inject root (the directory of the running `UtinniCoreDotNet.dll`) for `netstandard` and `UtinniCoreDotNet.PathContainment`, a pure unit-tested probe decision helper, and a csproj wiring that deploys `netstandard.dll` next to `UtinniCoreDotNet.dll` in the injected build. (The physical copy into `bin/Release/` is finalized by the rebuild/reassembly plan 15-17; this plan owns the resolver + the deploy rule.)
</objective>
