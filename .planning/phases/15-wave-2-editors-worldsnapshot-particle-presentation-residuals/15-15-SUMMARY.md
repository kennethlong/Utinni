# Phase 15 Plan 15: ParticleReadAssist inject-root probe (B7) Summary

`ParticleReadAssist.LocateCli` now probes the Utinni inject root in addition to its two existing candidates, so a deployed `utinni-cli.exe` resolves under injection (where the host-process dir is SWGEmu.exe's, not the Utinni deploy) — closing the 15-SMOKE B7 packaging/probe gap while preserving the honest CLI-absent degradation.

## What Changed

The B7 gap had two halves: (a) `utinni-cli.exe` is not shipped in the injection build (deploy is finalized by 15-17), and (b) `LocateCli` only probed the executing-assembly dir (`Plugins/TheJawaToolbox/`) and the host-process dir (under injection = the SWGEmu.exe dir, wrong). This plan owns half (b) — the probe-path fix so the deployed exe is actually discovered.

`LocateCli` now probes, in order:
1. **Executing-assembly dir** (unchanged) — `Plugins/TheJawaToolbox/`, where `TheJawaToolboxDotNet.dll` lives.
2. **Host-process dir** (unchanged) — correct for the standalone-editor-host case; wrong (SWGEmu.exe dir) under injection.
3. **Inject root** (NEW) — computed two levels up from the executing-assembly dir (`Plugins/TheJawaToolbox/<dll>` → `Plugins` → `bin/Release` = inject root) via nested `Path.GetDirectoryName`, each guarded for null.
4. **Bounded walk-up** (NEW) — if the two-levels-up dir doesn't carry the exe, walk up ≤3 parents from `asmDir` looking for the CLI directly OR an inject-root marker (`Launcher.exe` / `UtinniCoreDotNet.dll`), then probe the CLI in that marker dir.

The whole probe stays inside the existing `try/catch` (locating the CLI never throws into the click handler), and the method still returns `null` when no candidate exists — preserving the honest "utinni-cli.exe was not found next to the editor" degradation in the caller (`ExplainAsync` L87-92). The `decode-iff` dispatch and the click-handler error copy are unchanged.
