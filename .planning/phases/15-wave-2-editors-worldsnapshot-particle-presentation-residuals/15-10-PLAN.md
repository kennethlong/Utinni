<objective>
Close the secondary half of the A9 crash cluster + the GAP 2 stale-gizmo polish from 15-SMOKE.md:
- GAP 1.2: `WorldSnapshotImpl.Reload()` calls native `WorldSnapshot.Reload()` (re-reads the authored node list) but does NOT clear the editor undo stack — stale commands then hold dangling node state. Clear the undo stack on snapshot Load / Unload / Reload so no command can replay against a mismatched node list. (Combined with the 15-09 null-guards, this is belt-and-suspenders against the crash.)
- GAP 1.3: `Ctrl+Z` from the `FormSnapshotPlacements` child window is a silent no-op — the undo manager lives in `FormMain` and the plugin form has no route to it. Wire Ctrl+Z (and Ctrl+Y) from the placements window to the editor undo manager.
- GAP 2 (minor/polish): after `Delete selected` + snapshot reload, the in-world translate gizmo lingers at the old selected-node location. Clear/hide the gizmo when the selected node is removed or on snapshot reload.

Purpose: The undo stack today outlives the node list it was built against — the root structural cause behind the crash being reachable. Clearing it on every snapshot boundary, plus routing Ctrl+Z honestly, plus clearing the stale gizmo, makes the WS editor's undo affordance trustworthy for the PROD-W2-WS sign-off.

Output: A public `UndoRedoManager.Clear()`; an `IEditorPlugin` undo seam (`Undo` / `Redo` / `ClearUndoStack`) wired by `FormMain`; `WorldSnapshotImpl` clearing the stack + gizmo on snapshot boundaries; `FormSnapshotPlacements` routing Ctrl+Z/Y.

BINARY-COMPAT NOTE: this plan adds members to the `IEditorPlugin` interface (a public UtinniCoreDotNet API change). The TJT plugin DLLs (`TheJawaToolbox*.dll`) MUST be rebuilt in the same paired cross-repo commit — TJT is the only `IEditorPlugin` implementer and is rebuilt here, so the MissingMethodException-at-MEF-compose hazard (`feedback_caller_attrs_binary_compat`) is avoided by rebuilding both repos together.
