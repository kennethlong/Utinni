<decision>
Primary approach (RECOMMENDED) — **keep the button ENABLED, surface the honest reason on CLICK**:
  - `btnPreview.Enabled` becomes `hasDoc` (enabled whenever a doc is open), NOT gated on hook reachability.
  - `OnPreviewClicked`: if `hookReachable` is false (or `!Game.IsRunning`), do NOT attempt a retrigger —
    show the honest degraded reason via `lblStatus` (and the existing AI-results/dimmed surface if present),
    using `PreviewNoHookTooltip` (no client → `PreviewUnavailableTooltip`). Only when `hookReachable && Game.IsRunning`
    does it run the real hot-retrigger path (the 15-08 seam).
  - The tooltip (now on an enabled button) ALSO renders on hover — belt and suspenders.
  This makes the candor reachable by BOTH hover and click and removes the "disabled, no explanation" dead end,
  without ever over-promising a live hook (the message is the LOCKED degraded copy).

Alternative (document in SUMMARY if Primary proves awkward) — **keep the button disabled, wrap it in a
tooltip-bearing Panel**: place `btnPreview` inside a 1-control `Panel` and `toolTip.SetToolTip(pnlPreviewHost, …)`;
the panel (enabled) receives the hover events the disabled child does not, so the tooltip renders. Preserves
the disabled visual signal. Requires a Designer change.

Either is acceptable; pick ONE, keep the LOCKED copy, keep no-client vs no-hook distinct.
