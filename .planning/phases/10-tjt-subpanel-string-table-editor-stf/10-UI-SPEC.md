# Phase 10 — UI Design Contract: TJT String-table Editor (`.stf`)

> Visual and interaction contract for the Wave-1 localized-string editor: a **two-column
> (key, text) `ThemedDataGridView`** over `.stf` string tables (SWG `LocalizedStringTable`),
> with SOE-parity **T4** mutation on existing files (edit text, add entry, remove entry by
> key, rename key — `id` machine-managed and never user-edited), translation/bulk features
> (Find/Replace, CSV/TSV delta-import, sort + **live filter**, PO/gettext export), editor-local
> undo/redo, three save modes (loose-override / Save·Save-As / `.tre` repack; in-memory
> live-patch DISABLED inherited), and the locked CF-05 tier-(b) reload-status badge. Two entry
> points only (file picker + TRE Browser hand-off — **no IFF Editor hand-off**). Shipped inside
> The Jawa Toolbox (DEC-C4 / CF-06).
> Generated by gsd-ui-researcher.
>
> **PLATFORM: .NET Framework WinForms desktop UI — NOT web/CSS.** No component library, no
> shadcn, no Tailwind, no icon font. The "design system" is the existing Utinni themed WinForms
> control suite (`UtinniCoreDotNet.UI`) plus the Phase 9 `ThemedDataGridView` wrapper. Every
> token below is **INHERITED** from the approved Phase 7/8/9 UI-SPECs — none invented in this
> phase.
>
> **THIS SPEC EXTENDS `07-UI-SPEC.md`, `08-UI-SPEC.md`, AND `09-UI-SPEC.md` — it does not
> re-derive them.** Phase 7's design system / spacing / typography / color contract / host-
> placement rule, Phase 8's Wave-1-editor patterns (dirty marker, Save▾ drop-down,
> `FormSaveConfirmDialog`, editor-local undo/redo, reload affordance, status strip), and Phase
> 9's `ThemedDataGridView` token map + Find/Replace pane + view-only sort + cell-state overlays
> are treated as LOCKED and inherited verbatim. The sections below restate the locked tokens for
> the checker's six dimensions, then specify ONLY the new/changed surfaces Phase 10 adds.

## Host Placement Decision

**DECISION: Ship the String-table Editor as a NEW resizable `UtinniForm`
(`FormStringTableEditor`), registered in TJT's `GetForms()` list — exactly per the Phase 7 +
8 + 9 precedent rule (DEC-C4 / CF-06).** It is a sibling of `FormDatatableEditor`, not a
subclass (a shared abstract editor base is a deferred post-Wave-1 refactor). There is **NO IFF
Editor hand-off** — `.stf` is not IFF and never loads in `FormIffEditor` (format correction).

| Property | Value |
|----------|-------|
| Host type | `UtinniForm` (resizable, custom titlebar, `DrawName = true`, TJT icon — mirrors `FormDatatableEditor`) |
| Window title | `String-table Editor` — with a leading `● ` dirty marker per Phase 8 idiom |
| Default size | 1000 × 720 (persist `[StringTableEditor] width/height` to settings.ini; **narrower than the 1200 datatable default** — only two columns, but text rows can be long, so width still matters) |
| Minimum size | 760 × 520 (below this the grid + toolbar + status badge are unusable) |
| Open behavior | "Already open? `Activate()` : `Show()`" + single-document-per-window with dirty-discard prompt (08-05 singleton-form-hide-not-dispose: on `CloseReason.UserClosing` cancel close + `Hide()`) |
| Multi-document | V1 default: **single document per window** (open-replaces with a dirty-prompt). Tabbed/MDI deferred — same posture as Phases 8/9 |
| Settings persistence | `[StringTableEditor] width`, `height`, `findReplaceVisible`, `filterVisible`, `showIdColumn` (the read-only id-column toggle — see *Columns*), `looseOverrideDir` (mirrors Phase 8/9) |

**MEF SPI conformance (CON-M-01/02):** the new Form returns from `GetForms()`; the interface
is NOT widened (preserve STAB-04 foundations). `*Impl` separation per CON-T-05.

**Fallback if the Form path is blocked in execution:** degrade to a `StandalonePanel`
(dockable UserControl) at no less than 760×520; never the fixed 417px SubPanel. (Same fallback
as Phases 7/8/9.)

## Columns (NEW — the core Phase 10 surface decision)

The grid binds **two editable columns by default**, plus **one optional read-only diagnostic column**:

| Column | Header | Editable? | Widget | Notes |
|--------|--------|-----------|--------|-------|
| **Key** | `Key` | **Yes** | `DataGridViewTextBoxColumn` | The ASCII string name (the runtime lookup key). Renames validated against engine rules (see below). `FillWeight` ~35% — narrower than text. Sortable (view-only). |
| **Text** | `Text` | **Yes** | `DataGridViewTextBoxColumn`, `WrapMode = True` | The UTF-16LE localized string. **No validation, no transformation** (see Unicode fidelity). `FillWeight` ~65% — the dominant column. `AutoSizeMode = Fill`. Sortable (view-only). |
| **id** (optional) | `id` | **NEVER** | `DataGridViewTextBoxColumn`, `ReadOnly = true` | Machine-managed `u32`. **HIDDEN by default** (`showIdColumn` toggle OFF). When shown, rendered recessed (`Colors.PrimaryShadow()` bg / `Colors.FontDisabled()` fg) as a read-only diagnostic. Width ~64px, left of Key. **Never user-editable in any state** (CONTEXT locked floor + D-01: ids are internal lookup machinery; raw id editing is V2-deferred). |

**`sourceCrc` is NOT surfaced as a column.** It is internal machinery (a timestamp, not a content
hash — CONTEXT D-02b); the crc-on-edit *policy* is a planner decision (preserve / fresh
`int(time(0))` / 0), but the UI never shows or lets the user edit it. (If a future need surfaces,
it joins the `id` column as a second hidden read-only diagnostic — V2.)

**`showIdColumn` toggle:** a toolbar `UtinniToggleButton` labeled `Show id` (tooltip when OFF:
`Show the machine-managed id column (read-only diagnostic).`). Persists per-editor-instance via
`[StringTableEditor] showIdColumn` in settings.ini. Default OFF — the pure localization view is
two columns.

### Name validation (key column — CONTEXT D-01)

Key renames and added-entry names honor the engine's rules (researcher confirms exact rules from
`LocalizedStringTable.cpp` `validateStringName` / `fixupStringName` / `LocalizedStringTableRW::rename`):

- **Leading digit rejected** — a name that starts with `0-9` is invalid (engine `rename` rule).
- **Duplicate key rejected** — two entries cannot share a name.
- **Empty name rejected.**
- On reject: cell `BackColor = Color.Red`, status strip shows the validation copy at `Color.Red`,
  edit reverts (no commit). The grid's per-cell `CellValidating`/`CellEndEdit` enforces this
  before the edit reaches `IStringTableEditController`.

**Added entries (CONTEXT D-01 add semantics):** `Add entry` auto-assigns the next `id`
(`nextUniqueId`, machine-managed) and an auto-name of the SOE form `NNN_default` (per engine
`addString`); the new row is selected with the **Key** cell entering edit mode immediately so the
user can rename it. The auto-name is itself valid under the rules above.

## States

| State | Trigger | UI |
|-------|---------|----|
| **Empty (no document)** | Editor opened with no file loaded | Grid empty; centered dimmed `UtinniLabel` (`Colors.FontDisabled()`): heading `No string table open` + body `Open a .stf file from the toolbar, or use "Open in String-table Editor" from the TRE Browser.` Save / Undo / Redo / Reload / Add entry / Remove entry / Import / Export / Find / Replace / Filter all disabled. | **Loading** | File parsing on a background `Task` | Status strip: `Opening <name>…`. Window stays responsive (no modal spinner — inherited). |

| **Invalid key rename** | User typed a key failing name-validation (leading digit / duplicate / empty) | Key cell `BackColor = Color.Red`; status strip validation copy at `Color.Red`; edit reverts. |

## Unicode Fidelity (NON-BEHAVIOR — first-class contract, CONTEXT D-02 / SC4 / STAB-03)

The text-edit cell MUST round-trip UTF-16LE **byte-faithfully**. This is an explicit list of
things the editor must **NOT** do — surfaced here so the checker and executor treat it as a
load-bearing contract, not an afterthought:

- **NO smart-quote substitution.** Do not "auto-correct" `"` / `'` to typographic quotes. The
  engine's own `unfubarMicrosoftInvalidTextCharacters` rewrite is **deliberately NOT replicated**
  (CONTEXT D-02) — Utinni diverges from the engine to preserve text exactly.
- **NO ellipsis / dash / CR normalization.** `...` stays three periods; `--` stays two hyphens; CR
  bytes are preserved as-loaded.
- **NO typo-"fix" (STAB-03 regression guard).** The previously-corrupted `Jo�o` must NOT be
  silently "repaired" to `João` on load, and a correctly-loaded `João` must survive an
  edit→save→reload round-trip unchanged (SC4).
- **WinForms TextBox auto-correct off.** Whatever `DataGridViewTextBoxColumn` editing control is
  used must not apply any OS/IME smart-substitution that alters committed bytes.
- The CSV export is UTF-8 **with BOM** (D-03b) so non-ASCII survives the spreadsheet round-trip;
  CSV/PO import re-encodes back to UTF-16LE verbatim.

This non-behavior is automatically gated by the CLI `roundtrip-stf` golden (CF-02): our-reader ↔
our-writer byte-exactness on untouched entries, asserted on a `João`-bearing fixture.

## Accessibility / Interaction Notes (WinForms)

- **Keyboard (inherits Phase 8/9 + the new filter binding):**
  - `Ctrl+Z` / `Ctrl+Y` → editor-local undo / redo (CF-04; `ProcessCmdKey` caught at the form
    BEFORE the `DataGridView` sees them, per `FormDatatableEditor`). MUST NOT dispatch to the
    scene `UndoRedoManager`.
  - `Ctrl+S` → default Save (Save-in-place when `Source is LooseFile`, else Save As — inherited).
  - `Ctrl+F` → toggle Find pane, focus `txtFind`.
  - `Ctrl+H` → toggle Replace pane, focus `txtFind`.
  - `Ctrl+L` → toggle Filter row, focus `txtFilter` (planner discretion on the exact chord; must not collide with native grid keys).
  - `Esc` (while a Find/Replace/Filter input is focused) → collapse that pane / clear the filter.
  - `F3` / `Shift+F3` → Find next / previous when the Find pane is open.
  - `Delete` (while a row header is selected) → Remove entry (undoable; no modal).
  - Native `DataGridView` keys (arrows, Tab, Enter, F2 edit) preserved.
  - Tab order: toolbar → Find pane (if visible) → Filter row (if visible) → grid → status strip.
- **Read-only id is visibly read-only:** the `id` column (when shown) uses recessed
  `Colors.PrimaryShadow()` bg + `Colors.FontDisabled()` fg + `ReadOnly = true` — the read-only
  state is legible without relying on interaction-time discovery.
- **Dirty-glyph + color, not glyph-alone:** dirty / added cells use BOTH a row-header text glyph
  (`●` / `＋`) AND the accent color, so state is legible without color discrimination alone (Phase 8).
- **Thread marshaling (CON foundations):** file open / parse / save / CSV import all run on a
  background `Task`; every UI mutation marshals via `Control.Invoke` / `BeginInvoke`. The
  (disabled) live-patch path and any client-memory touch run on the game thread via
  `GameCallbacks.AddMainLoopCall` per CON-N-04.
- **No modal blocking for progress:** loading / saving / importing are inline status-strip text,
  never modal spinners. Modals are reserved for the CSV preview + the inherited risk confirmations.
- **Edits never silently lost:** a failed save RETAINS dirty state; closing/opening while dirty
  always routes through the discard-confirm modal (Phase 8 idiom).
- **High-DPI:** inherit `AutoScaleMode.Font` from `UtinniForm`; no hard-coded pixel sizes beyond
  the documented control metrics.
- **Singleton-form hide-not-dispose (LOCKED, inherited):** on `CloseReason.UserClosing`, cancel
  close + `Hide()` instead of disposing; host-shutdown reasons fall through normally.
