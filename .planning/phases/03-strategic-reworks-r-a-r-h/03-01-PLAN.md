## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| plugin author → callback registry | Plugin code calls Subscribe/Unsubscribe across the native↔managed boundary (P/Invoke for native registries; direct call for managed). Untrusted in the sense that a buggy plugin could pass a null fn-ptr or never Unsubscribe. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01-01 | Tampering | Subscribe handle (opaque int) | accept | Handle 0 reserved as invalid sentinel per D-09; Unsubscribe(0) returns false (Test 4 in Task 2). Out-of-range handles return false silently — no panic. Low-impact: a malicious plugin can only fail to unsubscribe, can't corrupt the registry of other plugins. |
| T-03-01-02 | Denial of service | Monotonic next_id counter (managed `int s_next{Name}Id`, native `static int s_next{Name}Id`) | accept | Counter overflow at 2^31 subscribes is not a realistic attack surface for V1 (single-process desktop tool, callbacks subscribed at plugin-init time, not at runtime hot-loop). Documented as a V2 watch-item if a plugin starts subscribing/unsubscribing at frame rate. |
| T-03-01-03 | Information disclosure | reflection-private-state-probe in tests | accept | Test-only code path; gated behind `[InternalsVisibleTo("UtinniCoreDotNet.Tests")]`. Does not appear in shipped UtinniPlugin code. |
| T-03-01-04 | Race | Snapshot iteration under lock (managed) | mitigate | The `.Values.ToArray()` copy under the per-callback lock isolates the iteration from concurrent Subscribe/Unsubscribe (Test 6-7 in Task 2 cover Subscribe-during-dispatch + Unsubscribe-during-dispatch without InvalidOperationException). Native side: no lock today (single-threaded SWG main-thread dispatch); vector-copy snapshot still protects against iterator invalidation from Subscribe-during-dispatch. |
| T-03-01-SC | Tampering | npm/pip/cargo installs | n/a | No package installs in this plan. xUnit 2.9.x and the rest of the test-deps are pinned from Phase 1; no new NuGet references introduced. |

Block-on-high: none. All threats above are accept-or-mitigate at L1.
