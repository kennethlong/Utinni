## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| "verbatim lift = clean build" | The 12-0x plans assumed lift-and-shift would build with at most "narrow escape hatches." Reality: every tool needed real source/build PORTING (engine-API drift, C++20, SAFESEH, CRT-compat). | advisory | Treat any further tool work as porting, not copying. Expect drift; build empirically and read the actual compiler/linker errors. |
| v6000 TREs as byte-exact refs | The retail `.tre` corpus (`D:\Sample-TRE-Files`) is Restoration **v6000 (encrypted)** — a newer format than the 2002 TreeFileBuilder emits (`0005`/`0006`). Using them as references is a dead end. | advisory | Only `0005`/`0006` source+`.rsp` pairs are valid TreeFileBuilder references. Confirm the `EERT00xx` version byte before treating any `.tre` as a reference. |
| Removing the build shims | `tools/Directory.Build.props` (include roots + `legacy_stdio_definitions.lib`) and the `UTINNI_TOOLS_NO_SHAREDLOG` define are LOAD-BEARING. Removing them breaks the standalone build. | advisory | Do not "clean up" these; they are the standalone-build glue, documented in DEPENDENCY-MANIFEST.md. |
