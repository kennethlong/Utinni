# Phase 9 — UI Design Contract: TJT Datatable Editor (`.tab`)

> Visual and interaction contract for the Wave-1 typed datatable editor: a typed DataGridView
> over `.tab` (FORM `DTII`) files with per-type cell widgets, SOE-parity T4 schema mutation
> (cells + rows + columns + column types) on existing files, CSV/TSV delta-import, Find/Replace,
> column-click view-sort, editor-local undo/redo, four save modes (loose-override / Save·Save-As /
> in-memory live patch DISABLED / `.tre` repack), and the locked CF-05 tier-(b) reload-status
> badge. Shipped inside The Jawa Toolbox (DEC-C4).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **PLATFORM: .NET Framework 4.7.2 WinForms desktop UI — NOT web/CSS.** No component library,
> no shadcn, no Tailwind, no icon font. The "design system" is the existing Utinni themed
> WinForms control suite (`UtinniCoreDotNet.UI`). Every token below is extracted from real code
> (`Colors.cs`, `UtinniForm.cs`, the themed controls, `TreDetailPane.cs`, the Phase 8
> `FormIffEditor` + `FormSaveConfirmDialog`) — none invented.
>
> **THIS SPEC EXTENDS `07-UI-SPEC.md` AND `08-UI-SPEC.md` — it does not re-derive them.** Phase 7's
> design system / spacing scale / typography / color contract / host-placement rule and Phase 8's
> Wave-1-editor patterns (dirty marker, Save▾ drop-down, status strip, FormSaveConfirmDialog
> destructive modal, editor-local undo/redo, reload affordance) are treated as LOCKED and
> inherited verbatim. The sections below restate the locked tokens for the checker's six
> dimensions and then specify ONLY the new/changed surfaces Phase 9 adds: the typed
> DataGridView grid + themed wrapper, per-type cell widgets, type-change cascade resolution
> modal, column reorder/delete safety-net modal, CSV import preview modal, Find/Replace slide-in
> pane, column-click sort indicator, DT_Comment-row frozen-header treatment, the three entry
> points, and the locked CF-05 reload-status badge.

## Host Placement Decision

**DECISION: Ship the Datatable Editor as a NEW resizable `UtinniForm` (`FormDatatableEditor`),
registered in the plugin's `GetForms()` list — exactly per the Phase 7 + Phase 8 precedent rule.**
The IFF Editor (`FormIffEditor`) STAYS as the chunk-level editor; it gains only a `Switch to typed
datatable view` menu item visible when the loaded IFF's root tag is `DTII` (D-10.3, manual
hand-off, NOT auto-route). The TRE Browser (`FormTreBrowser`) gains an `Open in Datatable Editor`
context-menu / button on selected entries recognized as `.tab` or `DTII` (D-10.2).

| Property | Value |
|----------|-------|
| Host type | `UtinniForm` (resizable, custom titlebar, `DrawName = true`, TJT icon — mirrors `FormIffEditor`) |
| Window title | `Datatable Editor` — with a leading `● ` dirty marker per Phase 8 idiom (see Dirty State) |
| Default size | 1200 × 760 (persist `[DatatableEditor] width/height` to settings.ini; mirrors `FormIffEditor`'s ini pattern — wider than 1100 because a typed grid needs more horizontal room than a hex view) |
| Minimum size | 900 × 560 (below this the grid + toolbar + status badge are unusable) |
| Open behavior | "Already open? `Activate()` : `Show()`" + single-document-per-window with dirty-discard prompt (08-05 singleton-form-hide-not-dispose pattern: on `CloseReason.UserClosing` cancel close + `Hide()` instead of disposing — matches the memory `singleton-form-hide-not-dispose` referenced by Phase 8 STATE.md) |
| Multi-document | V1 default: **single document per window** (open-replaces with a dirty-prompt). Tabbed MDI deferred — same posture as Phase 8 |
| Settings persistence | `[DatatableEditor] width`, `height`, `splitterDistance` (if used), `findReplaceVisible`, `editCommentRows` (toggle for the frozen DT_Comment row), `looseOverrideDir` (mirrors Phase 8) |

**MEF SPI conformance (CON-M-01/02):** the new Form returns from `GetForms()`; `GetSubPanels()`
stays as-is; the interface is NOT widened (preserve STAB-04 foundations).

**Fallback if the Form path is blocked in execution:** degrade to a `StandalonePanel` (dockable
UserControl) at no less than 1000×620; never the fixed 417px SubPanel. (Same fallback as
Phases 7 + 8.)

### Cell-state visual overlays (NEW, applied per-cell via `CellFormatting` event)

| State | Trigger | Visual |
|-------|---------|--------|
| **Clean** | Cell value matches original loaded bytes (CF-04) | Default — `Colors.PrimaryHighlight()` bg / `Colors.Font()` fg / no glyph |
| **Dirty (edited)** | User edited; value differs from original bytes | Cell `BackColor` stays default; cell `ForeColor = Colors.Secondary()` (accent). Row header gains a leading `● ` glyph (mirrors Phase 8 tree dirty-marker idiom) |
| **Added row** | Row was added via toolbar / context menu | Row header gains a leading `＋` glyph at `Colors.Secondary()`; row `DefaultCellStyle.ForeColor = Colors.Secondary()` |
| **Needs review (type-change cascade, D-04)** | Cell failed `DataTableColumnType::mangleValue()` after a column-type change | Cell `BackColor = Color.Red` (the documented destructive-color exception); cell `ForeColor = Colors.Font()` (kept legible on red); row header gains a leading `!` glyph at `Color.Red`. Save is BLOCKED while any "needs review" cell exists. Hover tooltip: locked copy below. |
| **Invalid edit (D-03 strict edit-time)** | User typed invalid input (e.g. `abc` in `DT_Int`) | The cell editor is the per-type widget (NumericUpDown / CheckBox / ComboBox / TextBox) — **invalid input is BLOCKED at keystroke by the widget** so this state should be unreachable for typed columns. For free-text columns (`DT_String` / `DT_Comment` / `DT_HashString` / `DT_PackedObjVars` / `DT_BitVector`) where parse-back validation runs on commit (planner discretion per CONTEXT), the cell `BackColor = Color.Red`; status-strip surfaces the validation copy (see Copywriting). Edit is rejected, cell value reverts. |
| **Frozen DT_Comment row** | First DT_Comment row (when present) AND `editCommentRows` toggle is OFF | Row `Frozen = true`; row `DefaultCellStyle.BackColor = Colors.PrimaryShadow()`; row `ForeColor = Colors.FontDisabled()`. Cells are non-editable in this state. |
| **Search-match (Find pane open + query has matches)** | Cell matches the current Find query | Cell `BackColor = Colors.Secondary()` at 40% opacity (planner discretion — implementable via `DataGridViewCellStyle.BackColor` on a custom value or via a paint override). Current-match cell additionally focused via `CurrentCell = match`. |
| **Sort indicator on a column header** | Column-click sort active (D-09) | Built-in `▲` / `▼` glyph (`SortOrder.Ascending` / `Descending`) at `Colors.Font()`. Hover tooltip: locked copy below. |

### Add-order rules (CF-09 — locked)

Per the `winforms-dockfill-zorder` memory, the Designer.cs `Controls.Add` order MUST be:

```
this.Controls.Add(this.gridSurface);      // Fill — added FIRST → front-most
this.Controls.Add(this.pnlStatus);        // Bottom
this.Controls.Add(this.pnlFindReplace);   // Top (collapsed by default)
this.Controls.Add(this.toolbar);          // Top — added LAST → outermost top
```

This is the exact pattern `FormIffEditor.Designer.cs` uses (`splitContainer` Fill added first,
then `pnlStatus`, then `toolbar`). Phase 9 inherits it verbatim. **DO NOT** `SendToBack` the
grid; **DO NOT** add the grid after siblings.

### Per-type cell widget contract (NEW, derived from CONTEXT D-03)

Strict edit-time validation. Invalid input is BLOCKED at keystroke by the widget itself. Status
copy on validation failure goes to `lblStatus` at `Color.Red` (Phase 8 idiom).

| `DT_*` column type | Edit widget | Keystroke validation |
|--------------------|-------------|----------------------|
| `DT_Int` | `UtinniNumericUpDown` (existing themed control) swapped in via `DataGridView.EditingControlShowing` | `DecimalPlaces = 0`; min/max from column type-spec or `int.MinValue` / `int.MaxValue` |
| `DT_Float` | `UtinniNumericUpDown` with `DecimalPlaces = 6` (planner may tune); `Increment = 0.1m` | min/max from column type-spec or `float.MinValue` / `float.MaxValue` |
| `DT_Bool` | `DataGridViewCheckBoxColumn` (no editor swap needed) | N/A — checkbox can only be `true`/`false` |
| `DT_Enum` | `DataGridViewComboBoxColumn` populated from type-spec string `e(a=0,b=1,c=2)[default]` | dropdown — user cannot type a non-member value |
| `DT_HashString` | `DataGridViewTextBoxColumn` (free text) + floating `UtinniLabel` (`Consolas 9pt`, `Colors.FontDisabled()`) anchored to the cell rect showing the computed hash (`0x{hash:X8}`) | No keystroke validation; hash recomputes on every keystroke |
| `DT_String` | `DataGridViewTextBoxColumn` (free text) | None — any string accepted |
| `DT_Comment` | `DataGridViewTextBoxColumn` (free text); read-only when row is the frozen header AND `editCommentRows` toggle is OFF | None |
| `DT_PackedObjVars` | `DataGridViewTextBoxColumn` + column-header `ToolTipText` carrying the format syntax hint (e.g. `name|type|value;name|type|value`) | Parse-back check on cell commit (`Validating`); on failure: revert + `lblStatus` red |
| `DT_BitVector` | `DataGridViewTextBoxColumn` + column-header `ToolTipText` carrying the format syntax hint (e.g. `[bit0,bit2,bit5]` or `b101010`) | Parse-back check on cell commit; on failure: revert + `lblStatus` red |

**Hash preview placement (DT_HashString):** the floating `UtinniLabel` anchors to the right of
the editing cell (or below if there isn't horizontal room), at `Consolas 9pt`,
`Colors.FontDisabled()`, format `→ 0x{hash:X8}`. The label is created on `CellBeginEdit` and
disposed on `CellEndEdit`. Do NOT use a per-row tooltip — the preview must be live as the user
types.

## Accessibility / Interaction Notes (WinForms)

- **Keyboard (inherits Phase 8 + adds grid + Find/Replace bindings):**
  - `Ctrl+Z` / `Ctrl+Y` → editor-local undo / redo (CF-06; ProcessCmdKey caught at the form
    BEFORE `DataGridView` sees them, exactly per `FormIffEditor.ProcessCmdKey`). MUST NOT
    dispatch to the scene `UndoRedoManager`.
  - `Ctrl+S` → default Save (Save-in-place when `Source is LooseFile`, else Save As — inherited
    Phase 8 logic).
  - `Ctrl+F` → toggle Find pane visibility, focus `txtFind`.
  - `Ctrl+H` → toggle Replace pane visibility, focus `txtFind`.
  - `Esc` (while Find/Replace pane focused) → collapse pane.
  - `F3` / `Shift+F3` → Find next / Find previous when Find pane is open.
  - `Delete` (while row header selected) → Remove row (undoable; no modal).
  - Native `DataGridView` keys (arrows, Tab, Enter, F2 edit) all preserved.
  - Tab order: toolbar → Find pane (if visible) → grid → status strip.
- **Dirty-glyph + color, not glyph-alone:** dirty / added / needs-review cells use BOTH a text
  glyph (`●` / `＋` / `!`) on the row header AND the accent color (or red for needs-review),
  so the state is legible without relying on color discrimination alone (inherits Phase 8).
- **Thread marshaling (CON foundations):** file open / parse / save / CSV import all run on a
  background `Task`; every UI mutation marshals via `Control.Invoke` / `BeginInvoke`. The
  in-memory live patch (inherited, disabled in Phase 9) and any forced reload touch the live
  client and MUST run on the game thread via `GameCallbacks.AddMainLoopCall` per CON-N-04
  (Phase 8 idiom).
- **No modal blocking for progress:** loading / saving / CSV-importing states are inline
  status-strip text, never modal dialogs. Modals are reserved for the risk confirmations + the
  type-change cascade resolution + the CSV import preview.
- **Edits never silently lost:** a failed save RETAINS the dirty state; closing / opening while
  dirty always routes through the discard-confirm modal (Phase 8 idiom).
- **High-DPI:** inherit `AutoScaleMode.Font` from `UtinniForm`; no hard-coded pixel sizes that
  fight DPI scaling beyond the documented control metrics.
- **Singleton-form hide-not-dispose pattern (LOCKED, inherited from Phase 8 STATE.md):** on
  `CloseReason.UserClosing`, the form cancels close + `Hide()` instead of disposing. This is
  the canonical pattern for plugin-registered `GetForms()` editors; Phase 9 must apply it from
  the start. Editor-host shutdown reasons (`ApplicationExitCall` / `WindowsShutDown` / etc.)
  fall through normally.

## Assumptions To Confirm (recorded, non-blocking)

UI question, a reasonable assumption consistent with the Phase 7 + 8 baseline is recorded here
rather than blocking on interactive questioning:

   styling wrapper at this phase. Phases 10 / 11 inherit it from TJT. **If a future phase needs
   it framework-side**, promote it via the same code-motion refactor pattern Phase 8 used for
   IFF primitives (no API surface change).
2. **Single-document-per-window** (open-replaces with a dirty-prompt) for V1; tabbed/MDI
   multi-doc deferred. Rationale: matches the `FormTreBrowser` + `FormIffEditor`
   "already open → Activate" single-window guard.
3. **`Reload in client` is a single toolbar button** whose enabled/disabled state + tooltip
   encode the CF-05 outcome (always tier (b) for datatables — locked). The button does NOT
   trigger a scene change; the badge spells out what the user must do (TJT chat-command load).

5. **The column reorder/delete safety-net modal REUSES `FormSaveConfirmDialog`** with the

   second-near-clone modal; the existing dialog's shape (heading + Color.Red body + accept-verb
   button + cancel button + optional checkbox) is a perfect fit. The session-suppress flag is

   `FormSaveConfirmDialog` reuse. Same rationale as #6.

## Amendments

### 2026-05-29 — enum syntax (RESEARCH Assumption A1)

NOTE: The DT_Enum cell-widget contract and CONTEXT D-03 previously cited the type-spec
grammar using square brackets with colon-separated label:value pairs. This was incorrect.
Per `DataTableColumnType.cpp:142-153` the
type-spec's first character is the type discriminator (`i`/`f`/`s`/`c`/`h`/`p`/`b`/`e`/`v`/`z`);
enum and bitvector lists are delimited by **parentheses** and use `=` as the label/value
separator (`e(label=val,label=val,…)[default]`), while **square brackets are reserved for the
optional `[default]` value group** (extracted via `getDelimStr(desc, '[', ']')`). The `z`
discriminator (cross-table enum) is out of scope for V1 per CONTEXT D-05 and routes to
`DT_Unknown` read-only handling per the R-03 recommendation. The corrected grammar
`e(a=0,b=1,c=2)[default]` is now used throughout this UI-SPEC and CONTEXT, and is implemented
verbatim by `DataTableColumnType.cs` in Plan 09-01.
