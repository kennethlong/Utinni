<objective>
Ship the **CLI-level structural correctness gate** for Phase 9. This plan introduces the
`utinni-cli roundtrip-tab` verb (CF-02 — analog of Phase 8's `roundtrip-iff`) that loads a `.tab`,
optionally applies a single structural mutation (`--mutate-cell R,C --mutate-value V` OR
`--remove-row N` OR `--remove-column N|name`), serializes via Plan 09-01's `DataTableWriter`,
re-parses the serialized bytes, and asserts byte-exact identity on the untouched cells. This is
the automated gate for Success Criterion 4 ("no silent schema corruption") — replicates the
Phase 4 `inspect-iff` / `decode-iff` and Phase 8 `roundtrip-iff` harness pattern verbatim.

The plan ships the verb (`RoundtripTabCommand.cs`), wires it into the CLI composition root
(`Program.cs`), ships a CLI-side fixture builder (`DataTableFixtureBuilder.cs` — mirrors Plan
09-01's framework-test fixture helpers because cross-project visibility prevents direct reuse;
both projects are small builders < 200 lines), and ships the golden test suite
(`RoundtripTabCommandTests.cs`) with the byte-exact-untouched-cells assertion as the SC4
structural gate.

**Byte-exact scope (iter-2 item 4 — codex HIGH):** the SC4 round-trip guarantees this plan gates
are deliberately scoped. Full-file byte-exactness is asserted only for the canonical/supported
DTII fixtures the `DatatableFixtureBuilder` produces (V0000 + V0001, built through the framework
primitives so they are valid by construction). For ANY mutation path, the guarantee narrows to
per-cell ROWS-payload-slice byte-exactness on the UNTOUCHED cells — NOT whole-file identity, and
NOT a promise that arbitrary hand-authored chunk layouts / unusual chunk order / extra trailing
bytes / type-spec spelling variants round-trip bit-for-bit. The objective and the threat model
state this boundary explicitly so the CLI envelope's `bytesEqualUntouched` flag is never read as a
universal byte-exact-on-everything claim.

**Why this decomposition:** Splitting the CLI gate into its own wave-2 plan (parallel with Plan
09-03 and depending on Plan 09-01) keeps each plan's context cost tractable, surfaces the JSON envelope + exit-code contract
at the earliest CI-observable point, and means the cross-AI review (`/gsd:code-review 09`) and
the verify-phase gate both have a tangible byte-level invariant to check from wave 1 onward
rather than waiting for wave 5's live-SWG smoke. Plan 09-02 has a `depends_on: ["09-01"]` edge
because the verb references Plan 09-01's published types; the executor MUST wait for Plan 09-01
to publish before Plan 09-02 Task 1 starts.

**Plan size:** 2 tasks (verb + tests). Mirrors Phase 8 Plan 08-02 (`roundtrip-iff`) shape.
</objective>
