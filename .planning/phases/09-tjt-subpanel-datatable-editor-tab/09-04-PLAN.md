## Execution Notes (iter-1 fix #8 + iter-2 item 6/8)

**Cascade-context tracking lives in the framework controller, NOT the form.**

Per checker WARNING #8 (iter-1) AND cross-AI review item 6 (iter-2, cursor HIGH), there is NO
form-local `lastCascadeContext` field on FormDatatableEditor. Cascade state is a framework-side
public read-only property on `DatatableEditController` so the cascade state machine is xUnit-testable.
**Any executor following the task bodies verbatim MUST NOT introduce a `lastCascadeContext` field —
the design was rejected; the controller owns the state.**

**Controller surface additions (Task 1):**
- `public PendingTypeChangeCascade PendingCascadeContext { get; }` (nullable reference type / or `PendingTypeChangeCascade?` if a struct) — exposing `{ int ColumnIndex, DataTableColumnType OldType, DataTableColumnType NewType, IReadOnlyList<MutableDataTableCell> NeedsReviewCellRefs }`.
- `public int NeedsReviewCount { get; }` (already in iter-0 plan; unchanged).
- Internal setter wired inside `ChangeColumnTypeCommand.Do` (sets `PendingCascadeContext`); cleared in `ChangeColumnTypeCommand.UndoOp` AND cleared automatically when `NeedsReviewCount` transitions to 0 via successful per-cell resolution edits (the controller recomputes `NeedsReviewCount` after each Apply and nulls `PendingCascadeContext` when it reaches 0).
- `public void MarkSaved()` (iter-2 item 8): sets `netAppliedCount = 0` (dirty baseline reset) AND iterates every cell to refresh its baseline so a subsequent edit re-computes dirtiness against the just-saved state. Recommended implementation: for each cell, if `cell.IsDirty`, the just-saved bytes are now the canonical bytes — re-capture the cell's current serialized payload as its new `originalSlice` and clear `isDirty` (a small internal `MutableDataTableCell.RebaselineAfterSave()` helper, OR re-run the load path on the freshly-serialized bytes — planner discretion; the simplest correct path is to re-serialize via DataTableWriter, re-parse, and swap the model — but that is heavy; the lighter path is per-cell rebaseline). Document the chosen mechanism in the SUMMARY. The seam MUST exist on the controller for Plan 09-05 to call; the rebaseline depth is planner discretion as long as `IsDirty` is false for all cells after MarkSaved and the next edit flips it true again.

**Form-side rewire (Task 2):**
- There is NO `lastCascadeContext` private field on `FormDatatableEditor`. (Iter-0 proposed one; it is rejected.)
- The `Resolve cascade…` toolbar button reads `controller.PendingCascadeContext` (null-check guard) to re-open `FormTypeChangeCascadeDialog` with the current affected-cell list (`PendingCascadeContext.NeedsReviewCellRefs`).
- The cascade-button visibility predicate is `btnResolveCascade.Visible = controller != null && controller.PendingCascadeContext != null` (set in `OnEditApplied`).
- On `Revert type change` in the cascade modal, the form calls `controller.Undo()` which rolls back the ChangeColumnType command; `ChangeColumnTypeCommand.UndoOp` clears `PendingCascadeContext`, so the next `OnEditApplied` hides the button.

**New xUnit facts in `DatatableEditControllerTests.cs` (Task 1) — FOUR required (three cascade + MarkSaved):**
1. `ChangeColumnType_Then_Undo_ClearsPendingCascade` — Apply ChangeColumnType with failing cells; assert `PendingCascadeContext != null`; Undo; assert `PendingCascadeContext == null` AND `NeedsReviewCount == 0`.
2. `ChangeColumnType_Then_ResolveAllCells_ClearsPendingCascade` — Apply ChangeColumnType with 3 failing cells; Apply 3 EditCellValue commands on those 3 cells with valid values; assert `PendingCascadeContext == null` after the 3rd successful resolution (and `NeedsReviewCount == 0`).
3. `ChangeColumnType_Then_PartialResolve_PendingCascadeRetained` — Apply ChangeColumnType with 3 failing cells; resolve 2 of 3 via EditCellValue; assert `PendingCascadeContext != null` AND `NeedsReviewCount == 1` AND `PendingCascadeContext.NeedsReviewCellRefs.Count == 1` (only the unresolved cell remains in the cell-refs list).
4. `MarkSaved_ResetsDirtyBaseline_AndNextEditFlipsDirty` (iter-2 item 8) — load fixture; Apply 2 EditCellValue commands; assert `IsDirty == true`; call `controller.MarkSaved()`; assert `IsDirty == false` AND all cells `IsDirty == false`; Apply one more EditCellValue; assert `IsDirty == true` again (the baseline moved to the saved state).

These facts add to the Plan 09-04 Task 1 fact count target (was ~30; now ~34-36 with these additions).
