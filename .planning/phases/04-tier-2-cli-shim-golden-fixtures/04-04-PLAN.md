<json_contract>
<!-- The validate-plugin JSON envelope. Stable as part of schemaVersion: 1. -->

```
{
  "command": "validate-plugin",
  "result": {
    "schemaVersion": 1,
    "directory": "<input dir argument>",
    "plugins": [
      {
        "id": "<dll-stem-name>",
        "path": "<absolute or relative path to the dll>",
        "kind": "managed|native|mixed",
        "exports": {
          "createPlugin": true,
          "destroyPlugin": true,
          "managedIPlugin": false,
          "managedIEditorPlugin": false
        },
        "checks": [
          { "id": "createplugin-export",      "status": "pass|fail|n/a", "detail": "..." },
          { "id": "destroyplugin-export",     "status": "pass|fail|n/a", "detail": "..." },
          { "id": "iplugin-export-shape",     "status": "pass|fail|n/a", "detail": "..." },
          { "id": "editor-plugin-export-shape","status": "pass|fail|n/a", "detail": "..." }
        ],
        "overallStatus": "pass|fail"
      }
    ],
    "summary": {
      "totalPlugins": 1,
      "passing": 1,
      "failing": 0
    }
  }
}
```

**Stable contract elements (schemaVersion: 1):**
- Top-level keys `command`, `result`. (Per Plan 04-01 envelope.)
- `result.schemaVersion`, `result.directory`, `result.plugins`, `result.summary` — all four MUST appear.
- Per-plugin object MUST carry `id`, `path`, `kind`, `exports`, `checks`, `overallStatus` — all six.
- `kind` ∈ `{managed, native, mixed}`. A DLL that exports createPlugin/destroyPlugin AND has a managed IPlugin Export is `mixed`. Pure-native (CrtMatchPlugin) is `native`. Pure-managed (WrongIPluginShape fixture is `managed` even when its Export attribute is malformed).
- `exports` is a stable four-key object — all four keys always present (true/false). Missing-export = false, not absent. Allows the React Flow consumer to render an exports matrix without checking key presence.
- Each `checks[].id` is a stable slug: `createplugin-export`, `destroyplugin-export`, `iplugin-export-shape`, `editor-plugin-export-shape`. A managed plugin's `createplugin-export` and `destroyplugin-export` checks have status `n/a`. A native plugin's `iplugin-export-shape` + `editor-plugin-export-shape` checks have status `n/a`. A `mixed` plugin runs all four.
- `overallStatus` = `pass` iff every check is `pass` or `n/a`; `fail` if any check is `fail`.

**React Flow portability (load-bearing):**
The plugin → checks shape is stable as part of schemaVersion: 1. Future React Flow tooling can ingest this directly: `plugins.flatMap(p => p.checks.map(c => ({ id: p.id + '/' + c.id, parentId: p.id })))`. Do NOT rename `id`/`status`/`overallStatus`/`summary` keys in cleanup refactors — they are the contract.

**Sort order for golden stability:**
- `plugins[]` is sorted by `id` (Ordinal string comparison). This makes the golden stable regardless of `Directory.GetFiles` enumeration order (which is OS-dependent — NTFS returns in some order, ReFS in another).
- `checks[]` is emitted in the fixed order listed above (createplugin → destroyplugin → iplugin → editor-plugin); this is the natural read order and matches the contract documented here. Sorting checks alphabetically would be wrong for human read; this is a per-array stability rule, not a Pitfall 10 violation (JsonOutput's recursive SortJObjectKeys does NOT reorder array elements, only object keys — which is the correct behavior).
- `exports` object's keys land in alphabetical order via JsonOutput's recursive sort: `createPlugin`, `destroyPlugin`, `managedIEditorPlugin`, `managedIPlugin`.
