<decisions_made>

Key load-bearing decisions reached during the 4-cycle planning loop (full audit in `04-REVISION-NOTES.md`):

- **IFF parser algorithm.** Top-level FORM IS the file (no file-bound check on top-level); nested chunks raise `NestedChunkOverflow` on parent-bound failure; leaf payload streaming-read EOF raises `Truncated`. `IffParseError` enum: `{ NegativeLength, ChunkLengthExceedsCap, NestedChunkOverflow, Truncated, MalformedFourCc }` — `ChunkLengthExceedsFile` removed as redundant. Each enum value reachable via a distinct deterministic code path. (Caught by Codex iter-3.)

- **PluginLoader.LoadErrors filter.** `LoaderObservation.LoadErrors` filters out `BadImageFormatException` / `"is not a valid Win32 application"` / `"not a managed assembly"` patterns via `PluginInspectionFilters.FilterNativeLoadErrors`. Native C++ DLLs in a MEF `DirectoryCatalog` produce these errors; filtering them gives a clean managed-plugin signal while preserving raw errors on the production Log sink. (Caught by Codex + Cursor iter-2 consensus.)

- **wrong-iplugin-shape dual-signal rule.** Separate `iPluginAttributePresent` (intent signal → drives `kind=managed`) from `iPluginInterfaceImplemented` (correctness signal → drives `iplugin-export-shape pass/fail`). A DLL with `[InheritedExport(typeof(IPlugin))]` on a non-implementing class produces `kind=managed` + `iplugin-export-shape=fail` deterministically. Same pattern for IEditorPlugin. (Caught by Codex + Cursor iter-4 consensus.)

- **No managed-fallback for native fixtures.** `cl.exe` required at build time per memory `project_vs2026_toolchain` (VS 2026 + VS 2022 both installed locally; GitHub Actions windows-2022 includes MSVC). Plan 04-04 PRE-FLIGHT fails hard with VS Build Tools install message if cl.exe absent. (Caught by Codex + Cursor iter-3 consensus.)

- **JSON envelope shape locked.** `{ schemaVersion: 1, command: "<verb>", result | error: { ... } }` with `schemaVersion` and `command` at the ENVELOPE ROOT, never nested. (Caught iter-1 HIGH-6.)

- **TreFile eager-read.** `Open(Stream)` eager-reads all record payloads into `byte[][]` cache to avoid lazy-seek-after-dispose. D-08 fixtures are <128KB so memory cost is trivial. (Caught iter-1 HIGH-4.)

- **PEReader for native plugin classification.** `System.Reflection.Metadata.PEReader` parses PE export tables without loading code — strongest T-04-EoP mitigation. Replaces the broken `LoadLibraryExW + LOAD_LIBRARY_AS_DATAFILE + GetProcAddress` combination. NuGet adds: `System.Reflection.Metadata 1.6.0` + `System.Collections.Immutable 1.5.0`. (Caught iter-1 HIGH-1.)

## Critical Anti-Patterns (do NOT repeat these)

| Pattern | Description | Severity | Prevention |
|---------|-------------|----------|-----------|
| Single-signal logic for attribute-vs-implementation | Task 4.1 originally said `iplugin-export-shape = managedIPlugin ? pass : fail` — single signal conflates "attribute present" with "interface implemented". Caught in iter-4 review. | advisory | Plan 04-04 Task 4.1 now specifies the dual-signal rule with explicit `iPluginAttributePresent` and `iPluginInterfaceImplemented` flags. Executor must implement both. |
| File-bound check on top-level chunk hides Truncated | Iter-3 caught that file-bound check on outer FORM fired before nested Truncated was reachable. Fixed by treating top-level FORM as "the file" with no file-bound check. | advisory | Plan 04-03 Task 3.1 documents the algorithm. Each `IffParseError` value is reachable via a distinct code path. |
| Per-plugin `loaderObserved` duplication | Iter-2 caught that `loaderObserved` was originally per-plugin but `PluginLoader.Load(dir)` operates on the whole directory — same value duplicated on every PluginReport. Hoisted to top-level `result.loaderObserved`. | advisory | Plan 04-04 `<json_contract>` locks the top-level shape. |
| Goldens assume `loadErrors: []` for native dirs | Iter-2 caught that `PluginLoader.LoadFromDirectory` catches MEF compose failures (incl. native DLLs' BadImageFormatException) into `LoadErrors` — the unfiltered list would NOT be empty. | advisory | Plan 04-04 specifies `FilterNativeLoadErrors` to drop the three documented native patterns before emission. |

None of these are `blocking` severity (no understanding-check gate needed); the prevention mechanisms are all baked into the plan text.
