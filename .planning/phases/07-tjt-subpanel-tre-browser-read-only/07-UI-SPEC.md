# Phase 7 — UI Design Contract: TJT TRE Browser (read-only)

> Visual and interaction contract for the first Wave-1 editor: a read-only, format-aware
> browser over the SWG `.tre` virtual filesystem, shipped inside The Jawa Toolbox (DEC-C4).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **PLATFORM: .NET Framework 4.7.2 WinForms desktop UI — NOT web/CSS.** There is no
> component library to select, no shadcn, no Tailwind, no icon-font dependency. The
> "design system" is the existing Utinni themed WinForms control suite (`UtinniCoreDotNet.UI`).
> Every token below is extracted from real code (`Colors.cs`, `UtinniForm.cs`, the themed
> controls, and `FormObjectBrowser.cs`) — none invented. The "60/30/10", "px sizes", and
> "line-height" framing in the standard template is mapped onto WinForms equivalents
> (point sizes, `Color.FromArgb`, control row pitch) so the checker's six dimensions still apply.

---

## Host Placement Decision (resolves RESEARCH Open Question #3)

**DECISION: Ship as a resizable `Form` (a `UtinniForm` subclass registered in the plugin's
`forms` list), NOT a fixed-417px `SubPanel`.** This is the one genuinely open UI decision and
it is resolved here with rationale and a fallback.

| Option | Verdict | Why |
|--------|---------|-----|
| **Resizable `Form` (UtinniForm)** | **CHOSEN** | The two-region browse-and-inspect UX (a 100k+ entry tree + a 5-section detail pane) needs horizontal room a 417px column cannot give. `FormObjectBrowser` — the exact analog this phase follows (D-03) — is already a `UtinniForm` in the `forms` list, not a SubPanel. A user-resizable, persisted-size window is the correct host for a dense data browser. |
| Fixed-417px `SubPanel` in a `SubPanelContainer` | Rejected | `SubPanel` is hard-locked to 417px via `OnResize` override (`SubPanel.cs:58-65`); `SubPanelContainer` is a `TopDown` `FlowLayoutPanel` MinimumSize 420 wide. A tree + multi-section detail pane cannot coexist in 417px without horizontal scrolling both regions — unacceptable for a primary browse surface. SubPanels are designed for stacked control clusters (toggles, sliders), not data browsers. |
| `StandalonePanel` (dockable UserControl in main host) | Deferred fallback | Viable and may become the long-term home if TJT adds a docking host, but TJT today aggregates control clusters as SubPanels and full tools as Forms. The Form path matches existing precedent with zero new host infrastructure. |

**Precedent set for Phases 8-11 (general Wave-1-editor rule):** Wave-1 *editors* (TRE browser,
IFF/datatable/STF/object-template editors) ship as **resizable `UtinniForm` windows** registered
via `GetForms()`. Reserve `SubPanel` strictly for the existing in-world *control clusters*
(scene/snapshot/player/freecam/graphics). Each editor Form opens via the existing
"already-open? Activate : Show" guard from `FormObjectBrowser.Create()`. This is not binding on the
deferred ImGui-HUD presentation (D-04) — it governs the WinForms surface only.

**Fallback if the Form path is blocked in execution:** degrade to a `StandalonePanel`
(dockable UserControl) at no less than 900×600; never the fixed 417px SubPanel.

**MEF SPI conformance (CON-M-01/02):** the plugin returns the new Form from `GetForms()`;
`GetSubPanels()` stays `null`; `GetStandalonePanels()` keeps returning the existing control
container. Interface is NOT widened (preserve the foundation).

## Design System

| Property | Value |
|----------|-------|
| Tool | none (WinForms; no web design system) |
| Preset | not applicable |
| Component library | Existing Utinni themed WinForms controls (`UtinniCoreDotNet.UI.Controls`) |
| Icon library | none (no icon font). Type cues = single-letter / short-tag badges drawn into `TreeView`/`ListView` via the existing `ImageList` mechanism, or text glyphs. Do NOT add an icon-font dependency. |
| Font | Default WinForms UI font — `Microsoft Sans Serif 8.25pt` (the `AutoScaleMode.Font` / `AutoScaleDimensions(6F,13F)` baseline used by every existing Utinni form). Titlebar window name only: `Arcon 12pt` (from `UtinniForm.nameFont`). |
| Theme | Fixed dark theme (`Colors.Theme = Themes.Dark`). The browser MUST pull all colors from `UtinniCoreDotNet.UI.Theme.Colors` — never hard-code `Color.FromArgb(...)` literals (the GraphicsPanel accent-button literal is a known anti-pattern; use `Colors.Secondary()`). |

**Mandatory control reuse (Don't Hand-Roll):** the browser is built ONLY from existing themed
controls — no new custom-painted widgets unless a gap is proven:

| Need | Use this existing control |
|------|---------------------------|
| Virtual-path navigation tree | `System.Windows.Forms.TreeView` themed exactly as `FormObjectBrowser` does: `BackColor = Colors.PrimaryHighlight()`, `ForeColor = Colors.Font()`, `BorderStyle = None` |
| Search/filter input | `UtinniTextbox` (themed `TextBox`, `BackColor = Colors.PrimaryHighlight()`) |
| Detail metadata header rows + section labels | `UtinniLabel` |
| Type-specific tabular views (datatable rows, STF entries, object-template fields) | `System.Windows.Forms.ListView` (Details mode, themed `BackColor = Colors.PrimaryHighlight()`, `ForeColor = Colors.Font()`, `BorderStyle = None`) |
| IFF chunk tree | a second themed `TreeView` (same theming as the nav tree) |
| Window chrome / resize / titlebar | `UtinniForm` base (custom titlebar, `Resizable = true`, drop shadow) |
| Collapsible detail sections | `CollapsiblePanel` (the existing expand/collapse panel used by SubPanelContainer) |
| Right-click actions (Copy path, Copy CRC) | `UtinniContextMenuStrip` |
| Buttons (e.g. "Copy", retry) | `UtinniButton` |
| Splitter between tree and detail | `System.Windows.Forms.SplitContainer` (themed `BackColor = Colors.Primary()`) |

## Layout Contract (WinForms)

### Window

| Property | Value |
|----------|-------|
| Host type | `UtinniForm` (resizable, custom titlebar, `DrawName = true`, `IconImage` = TJT icon per `FormObjectBrowser`) |
| Window title | `TRE Browser` |
| Default size | 1100 × 700 (persist to `settings.ini` `[TreBrowser] width/height` like `FormObjectBrowser` does for ObjectBrowser) |
| Minimum size | 760 × 480 (below this the two-region split is unusable) |
| Open behavior | "Already open? `Activate()` and return null : `Show()`" guard, identical to `FormObjectBrowser.Create()` |
| KeepOnTop toggle | Optional titlebar toggle mirroring `FormObjectBrowser.chkKeepOnTop` (persist to ini); not required for V1 |

### Two-region split

A single horizontal `SplitContainer` divides the client area:

| Region | Side | Default width | Min width | Resize |
|--------|------|---------------|-----------|--------|
| Navigation tree + search | Left (`Panel1`) | 360px | 240px | user-draggable splitter; persist `SplitterDistance` to ini |
| Detail pane | Right (`Panel2`) | remaining (~720px) | 420px | fills; vertically scrollable |

- `SplitContainer.Orientation = Vertical` (vertical splitter bar between two horizontal panels).
- Splitter bar: `BackColor = Colors.Primary()`, width 4px, fixed-panel none.
- Both panels: `BackColor = Colors.Primary()` (the dominant surface).

### Left region — Navigation tree

Top-to-bottom flow inside `Panel1`:

1. **Search/filter bar** (`UtinniTextbox`) docked top, full width, height 22px, 3px inset on all sides.
   - Placeholder/empty behavior: when empty, the tree shows the full hierarchy.
   - Debounce: **250ms** after the last keystroke before re-filtering (the tree is 100k+
     entries — filtering on every `TextChanged` synchronously, as `FormObjectBrowser` does today
     on its much smaller `object/` subset, would jank). Use a single restarting WinForms `Timer`.
   - Filter semantics (resolves the D-11 planner-discretion UX): **case-insensitive substring**
     match on the full virtual path (matches `FormObjectBrowser`'s `Contains` behavior, extended
     to the whole path). Substring is the default; glob is out of scope for V1.
   - Match handling: prune the tree to ancestor chains that contain ≥1 matching leaf; expand
     those chains; the matched substring is **bolded** in the node label (the only use of the
     bold weight — see Typography).
   - Optional type facet: a single `UtinniComboBox` ("All types ▾") to the right of the search
     box, 120px wide, filtering by asset extension group (datatable / stringtable / template /
     mesh / shader / other). V1-optional; if included, place inline with the search box.

2. **Tree** (`TreeView`) docked fill below the search bar.
   - Theming: `BackColor = Colors.PrimaryHighlight()`, `ForeColor = Colors.Font()`, `BorderStyle = None`,
     `HideSelection = false`, `ShowLines = true`.
   - Hierarchy: SWG virtual-path (`object/…`, `appearance/`, `shader/`, `datatables/`, `string/…`)
     built by splitting paths on `/` (the `FormObjectBrowser` `LoadRepo()` nesting algorithm,
     generalized to ALL directories and ALL extensions — not just `object/` and `.iff`).
   - **Lazy / on-demand expansion (REQUIRED — 100k+ entries, Pitfall 5):** populate only the
     top-level directory nodes eagerly; add a dummy child to each unexpanded directory so the
     expand glyph shows; populate real children in the `BeforeExpand` handler. Never build all
     213k nodes up front. Background-load the directory index on a `Task` and marshal node
     inserts to the UI thread via `Control.Invoke`.
   - **Node type cues:** leaf nodes carry a short type badge via a shared `ImageList` (16×16)
     OR a bracketed text tag suffix, e.g. `creature_bantha.iff  [TMPL]`. Allowed tags:
     `[IFF] [TAB] [STF] [TMPL] [MESH] [SKEL] [ANIM] [SHDR] [—]`. Pick ONE mechanism
     (ImageList or text tag) and apply it consistently; text tag is the lower-risk default.
   - **Loaded/resolvable overlay (D-05 hybrid):** entries present in the live `Game.Repository`
     harvested set render at full `Colors.Font()` (WhiteSmoke); entries that exist on disk but
     are NOT currently loaded/resolvable render at `Colors.FontDisabled()` (#646464, dimmed).
     A short legend label sits under the tree: `Dimmed = on disk, not currently loaded`.
     The overlay is best-effort: if no game session is running, ALL nodes render at full color
     (disk truth only) and the legend reads `Overlay unavailable — no live client`.

### Right region — Detail pane

A vertically-scrolling stack (a `Panel` with `AutoScroll = true`, `BackColor = Colors.Primary()`),
populated on `TreeView.AfterSelect`. Five collapsible sections, top to bottom (each a
`CollapsiblePanel`; metadata header + banner open by default):

1. **Metadata header** (always visible, not collapsible)
   - Label/value rows (`UtinniLabel` pairs, 16px row pitch): Virtual path · File size (bytes +
     human) · Source `.tre` archive · CRC (hex) · Compression (none / zlib / deflate).
   - Label column left-aligned at x=3; value column at x=140.
   - A `Copy path` / `Copy CRC` affordance via `UtinniContextMenuStrip` on right-click (read-only —
     copying text to clipboard is allowed; it is NOT a write/export of the asset).

2. **Type + version banner** (open by default)
   - One prominent `UtinniLabel` row stating the decoded type and the root FORM tag + version,
     e.g. `Datatable (DTII / 0001)` or `Object Template (CREO / 0006)`.
   - Banner background tint uses `Colors.Secondary()` (#007ACC) as a thin 2px top accent rule
     ONLY (matching `UtinniForm`'s titlebar accent line) — the accent is reserved, see Color.
   - **Encrypted/enumerate-only state (D-07):** for v6000 / v5000 archives where payload is
     obfuscated, the banner reads `Encrypted payload (v6000) — enumerate-only` and the
     remaining content sections (3-5) are replaced by a single info panel (see States below).

3. **Universal IFF chunk tree** (open by default when payload is readable)
   - A themed `TreeView` (same theming as the nav tree) rendering FORM/chunk hierarchy from
     `IffDocument.Root` (`Formats/Iff`): each node shows `TAG  ·  size bytes  ·  @offset`.
   - This is the exact surface Phase 8's IFF editor will make editable (D-13) — keep it a
     standalone, reusable control.

4. **Type-specific structured view** (open by default when payload is readable)
   - Dispatched on root FORM tag (D-12). Rendered as a themed `ListView` (Details) or
     label grid as appropriate:
     - **Datatable:** `ListView` with a column per datatable column (header = column name +
       type), rows = decoded cells.
     - **String-table:** `ListView` 2-col (`String ID` | `Text`), one row per entry.
     - **Object template:** `ListView` 3-col (`Field` | `Value` | `Inherited from`), showing the
       inherited-field walk.
     - **Mesh / skeletal mesh / skeleton / animation:** label grid of structural counts
       (vertex count, shader count, joint count, frame count, joint tree as a small read-only
       `TreeView`).
   - For unrecognized types: this section is hidden; the IFF chunk tree (section 3) and raw hex
     peek (section 5) still render.

5. **Raw hex peek** (collapsed by default)
   - A monospace read-only view of the first N bytes (cap at the first 4 KB) of the selected
     payload when readable. Monospace exception to the body font (see Typography). Render in a
     read-only `UtinniTextbox` (Multiline) or a fixed-pitch label.
   - Hidden entirely when the payload is encrypted/enumerate-only.

## States

| State | Trigger | UI |
|-------|---------|----|
| **Loading (tree)** | Panel opens; directory index building on background `Task` | Disabled tree + a status `UtinniLabel` at top of left region: `Loading archive index…`. No modal spinner (WinForms convention); the window stays responsive. |
| **No selection (empty detail)** | Panel open, nothing selected in tree | Detail pane shows a single centered `UtinniLabel` (dimmed, `Colors.FontDisabled()`): heading `No file selected` + body `Select a file in the tree to inspect its structure and contents.` |
| **Loading (detail)** | A node selected; single payload reading on demand | Metadata header populates immediately (from the already-enumerated TOC); content sections show `Decoding…` until the on-demand read + decode completes. |
| **Encrypted / enumerate-only** | Selected entry is in a v6000 / v5000 (obfuscated) archive (D-07) | Metadata header + type/version banner render normally; sections 3-5 are replaced by an info panel: heading `Encrypted payload (v6000)` + body `This archive's contents are obfuscated and cannot be decoded in-app. Metadata is available above. Extract with TreeFileExtractor.exe to inspect raw bytes.` Uses dimmed font, no accent, no error-red. |
| **Parse failure** | IFF/decoder throws on a readable payload | Sections 3-5 replaced by an error panel: heading `Could not decode this file` + body `<reason from parse exception> The file may be truncated or use an unsupported layout. Other files are unaffected.` Heading uses the destructive color (see Color); body uses normal font. Never crash the panel — one bad file must not take down the browser. |
| **Overlay unavailable** | No live SWG session (`!Game.IsRunning`) | Tree renders disk truth at full color; legend reads `Overlay unavailable — no live client`. Not an error. |

## Spacing Scale (WinForms-mapped)

WinForms uses device pixels at 96 DPI; the existing controls use a tight 3px inset convention,
NOT an 8-point web scale. The declared scale below is the multiples-of-4-aligned set the new
browser uses, with the documented WinForms exceptions that match existing code.

| Token | Value | Usage |
|-------|-------|-------|
| inset | 3px | Control inset from panel edge (matches every existing SubPanel: `Location = (3, …)`) |
| xs | 4px | Splitter bar width; gap between inline controls |
| sm | 8px | Gap between metadata label/value groups |
| md | 16px | Detail-section row pitch; vertical gap between sections |
| lg | 24px | Collapsible-section header height + content top offset (`CollapsiblePanel` uses 24/26) |
| xl | 32px | Titlebar height (`UtinniForm.titleBarHeight = 32`, fixed) |

Exceptions (WinForms-mandated, not violations):
- **3px control inset** is the established Utinni convention (every SubPanel `Location.X = 3`); it is the canonical edge gutter, used in place of a 4px token at panel edges.
- **22px text-input height / ~23px tree-row pitch / 17px toggle height** are WinForms default control metrics, kept as-is for theme consistency.
- **32px titlebar** is fixed by `UtinniForm` and cannot change.

## Typography

WinForms point sizes (not web px). Two weights only: Regular and Bold. Bold is reserved.

| Role | Size | Weight | Notes |
|------|------|--------|-------|
| Body / tree nodes / list cells / metadata values | 8.25pt Microsoft Sans Serif | Regular | The framework default; do not override per-control |
| Label / section headers / metadata keys | 8.25pt Microsoft Sans Serif | Regular | Same size; differentiated by position + accent rule, not by size |
| Window titlebar name | 12pt Arcon | Regular | `UtinniForm.nameFont` — titlebar only |
| Search-match highlight + type/version banner emphasis | 8.25pt Microsoft Sans Serif | **Bold** | The ONLY use of Bold: (a) the matched substring inside a filtered tree node, (b) the type+version banner text |
| Raw hex peek | 9pt Consolas (monospace) | Regular | Exception: fixed-pitch is required for byte alignment |

Line height: WinForms controls manage their own row metrics; do not set custom line heights.
Tree/list row pitch is the control default (~17-23px). This satisfies the "readable, consistent
vertical rhythm" intent of the checker's typography dimension within WinForms norms.

## Color

Mapped from `UtinniCoreDotNet.UI.Theme.Colors` (fixed Dark theme). All values MUST be pulled via
the `Colors.*()` accessors at runtime — the hex below is documentation of what those return.
No raw `Color.FromArgb` literals in the browser code.

| Role | Accessor | Value | Usage |
|------|----------|-------|-------|
| Dominant (~60%) | `Colors.Primary()` | #282828 (40,40,40) | Form background, detail-pane background, splitter, section backgrounds |
| Secondary surface (~30%) | `Colors.PrimaryHighlight()` | #404040 (64,64,64) | Tree background, search input, list/grid backgrounds (the raised data surfaces) |
| Shadow / deep recess | `Colors.PrimaryShadow()` | #191919 (25,25,25) | Optional inner recesses / pressed states |
| Accent (~10%) | `Colors.Secondary()` | #007ACC (0,122,204) | RESERVED — see list below |
| Foreground text | `Colors.Font()` | #F5F5F5 WhiteSmoke | All primary text + loaded/resolvable tree nodes |
| Dimmed / not-loaded | `Colors.FontDisabled()` | #646464 (100,100,100) | On-disk-not-loaded tree nodes; empty-state text; disabled controls |
| Control border | `Colors.ControlBorder()` | #646464 (100,100,100) | 1px control outlines where drawn |
| Destructive | `Color.Red` (as used by `UtinniForm` close button) | #FF0000 | Parse-failure error heading text ONLY |

**Accent (`#007ACC`) reserved for — explicit list (never "all interactive elements"):**
1. The 2px top accent rule on the window titlebar (inherited from `UtinniForm.OnPaint`).
2. The 2px top accent rule on the type/version banner section.
3. The selected tree node / selected list row highlight (system-selection styling).
4. A single primary action accent button IF one is added (e.g. `Copy`), styled like the
   existing `Colors.Secondary()` accent buttons.

Accent is NOT used for: ordinary buttons, borders, labels, section dividers, or the loaded-state
tree text (that uses full-vs-dimmed `Font()`/`FontDisabled()`, not accent color).

**Destructive color** (`Color.Red`) is used ONLY for the parse-failure error heading. There are
NO destructive *actions* in this phase — the browser is strictly read-only (no delete, no
overwrite, no export). The destructive color here flags an error condition, not a user action.

## Copywriting Contract

This phase is read-only: there is no save/edit/export CTA and no destructive action. The
"Primary CTA" is the core read interaction (selecting a file to inspect). All copy is sentence
case, concise, and tells the user what to do next.

| Element | Copy |
|---------|------|
| Primary action (read) | Select a file to inspect — there is no save/edit affordance (read-only by design, D-01) |
| Search placeholder / hint | `Filter files…` |
| Type-facet default | `All types` |
| Empty state heading (no selection) | `No file selected` |
| Empty state body | `Select a file in the tree to inspect its structure and contents.` |
| Tree loading status | `Loading archive index…` |
| Detail loading status | `Decoding…` |
| Overlay legend (live) | `Dimmed = on disk, not currently loaded` |
| Overlay legend (no client) | `Overlay unavailable — no live client` |
| Encrypted state heading | `Encrypted payload (v6000)` |
| Encrypted state body | `This archive's contents are obfuscated and cannot be decoded in-app. Metadata is available above. Extract with TreeFileExtractor.exe to inspect raw bytes.` |
| Parse-failure heading | `Could not decode this file` |
| Parse-failure body | `<exception reason>. The file may be truncated or use an unsupported layout. Other files are unaffected.` |
| 5000-version note (if a 5000 archive appears) | `Recognized TRE version 5000 — layout not yet verified; enumerate-only.` |
| Destructive actions | None (read-only phase; no confirmations needed) |

## Accessibility / Interaction Notes (WinForms)

- **Keyboard:** TreeView arrow-key navigation + Enter-to-select is native; search box is the
  initial focus; Tab order = search → type facet → tree → detail sections.
- **Thread marshaling (CON foundations):** the disk enumeration runs on a background `Task`;
  every UI mutation (node insert, detail populate) marshals via `Control.Invoke`. The live
  `Game.Repository` overlay read follows the `Control.Invoke` / `GameCallbacks.AddMainLoopCall`
  pattern (`FormObjectBrowser` precedent) — never touch UI controls from the game thread.
- **No modal blocking:** loading states are inline status labels, never modal dialogs, so the
  window stays draggable/closable during the multi-second index build.
- **High-DPI:** inherit `AutoScaleMode.Font` from `UtinniForm`; do not hard-code pixel sizes that
  fight DPI scaling beyond the documented control metrics.
