# Phase 23 — UI Design Contract

> Visual and interaction contract for the Tier-B in-place hex-driven template builder and template
> management surfaces. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **PLATFORM NOTE (read first):** This is a **WinForms desktop editor** (net4.7.2) inside The Jawa
> Toolbox, NOT a web app. There is no CSS/HTML/shadcn/component-library/design-token system. The
> "design system" is the established TJT WinForms idiom: `UtinniForm` windows, `UtinniButton` /
> `UtinniLabel` / `UtinniTextbox` / `UtinniContextMenuStrip` controls, `SplitContainer`s, themed
> `TreeView`, the `Colors.*()` theme accessors, and Pitfall-8 layout rules. The "Spacing / Typography
> / Color" sections below are expressed in **WinForms terms** (control docking/anchoring, fixed pixel
> strip heights, native font, `SystemColors`/theme accessors), not web tokens. The hard rule for this
> phase: **reuse the existing `FormIffEditor` visual language verbatim** — the Tier-B builder is a new
> pane MODE inside `pnlLeafEditor`, alongside the existing hex (`txtHex`) and text (`txtText`) modes,
> not a new window and not a new visual style.

## Host Surface & Layout Contract

The Tier-B builder is the **fourth leaf-pane mode** of `FormIffEditor.pnlLeafEditor`. Tree selection
already routes through `OnTreeAfterSelect` → `ShowLeafReadOnly(leaf)` which calls
`leaf.GetPayloadCopy()`. The existing modes are: **(read-only)** no-selection, **(container)**
summary, **(leaf-hex)** `txtHex`, **(leaf-text)** `txtText`. This phase adds **(leaf-template)**.

### Mode entry & coexistence

- The existing `btnHexMode` / `btnTextMode` toggle buttons live in `pnlLeafHeader` (Dock.Right, 50px
  each). Add a third toggle **`btnTemplateMode`** ("Template", Dock.Right, 50px) in the same header
  strip, to the LEFT of the existing two (added FIRST among the Dock.Right cluster so it renders
  leftmost of the three — mirror the reverse-add order the Designer already uses for the toolbar).
- `btnTemplateMode` is **always visible when a leaf is selected** (unlike Hex/Text which only appear
  for ASCII-ish leaves). It is the new default mode **only when a template auto-applies** (D-05/D-07
  green); otherwise the leaf opens in Hex as today (no behavior change for built-in-claimed files).
- Switching modes never loses edits: each mode commits on `Leave`/`Validating` (the existing
  per-mode commit rule, never per-keystroke — avoids the undo storm flagged in 08-REVIEWS MEDIUM-6).

### Tier-B pane internal layout (Pitfall 8 — LOCKED)

The template pane is a single `Panel` (`pnlTemplate`, Dock.Fill, added to `pnlLeafEditor` **before**
its docked siblings so Fill renders front-most — the verbatim Pitfall-8 rule the Designer already
follows for `txtHex`). Its interior is a **nested vertical `SplitContainer`** (`splitTemplate`,
Orientation = Horizontal so the splitter is horizontal → top/bottom panels):

```
pnlTemplate (Dock.Fill, front-most)
├── pnlTemplateStatus (Dock.Bottom, 22px)  ── the live round-trip indicator strip (see States)
└── splitTemplate (Dock.Fill, nested SplitContainer, Orientation=Horizontal)
    ├── Panel1 (TOP)  : raw-byte view  ── monospace hex grid, selectable, annotated spans tinted
    └── Panel2 (BOTTOM): decoded field list ── the typed FieldRecord rows (add/remove/reorder)
```

**LOCKED layout invariants (Pitfall 8 — `[[feedback_winforms_dockfill_zorder]]`):**
1. Every `Dock.Fill` child is added to its parent's `Controls` collection **first** (front-most),
   docked siblings (Top/Bottom/Right) added after. Never `SendToBack` a Fill control.
2. On the nested `SplitContainer`, set `Size` **before** `SplitterDistance` (a fresh SplitContainer
   is 150px wide; setting a larger SplitterDistance first throws `InvalidOperationException` — which
   from the ctor fails the whole plugin's MEF load). Mirror the `splitContainer` Designer block
   (Size → SplitterWidth=4 → SplitterDistance → Panel*MinSize) verbatim.
3. Wrap the splitter-distance ini-restore in the same guard+try/catch the ctor already uses for the
   outer splitter, so a stale ini value can never bubble out of the ctor.
4. Guard the `FormIffEditor` ctor / any new control ctor against MEF silent-reject (no throwing in
   construction; defaults survive a bad ini). Reference `[[feedback_caller_attrs_binary_compat]]`:
   do NOT add defaulted `[Caller*]` params to any public method the pre-built plugin DLLs call.

### Pane orientation decision (was Claude's Discretion — **DECIDED**)

**Top = raw bytes, Bottom = decoded fields, horizontal splitter.** Rationale: the gesture flows
top→down (select bytes up top → they appear as a typed row below), matching reading order; the hex
grid wants width more than height; the field list grows downward as the template grows. The outer
window stays the existing vertical split (tree left / editor right) — unchanged.

### Undo stack decision (was Claude's Discretion — **DECIDED**)

**Ride the existing `IffEditController` undo stack.** A template field-value edit is just a
`leaf.SetPayload(kernelEncodedBytes)` — exactly the `IffEditCommands.EditLeafPayload` command the
controller already tracks (RESEARCH A3, LOW risk). Ctrl+Z / Ctrl+Y / Ctrl+S are already captured in
`ProcessCmdKey` regardless of focused control; the template pane inherits this for free. **Template
*authoring* (assigning a type to a byte range, editing the FieldRecord list) is a SEPARATE concern
from the document edit** — authoring mutates the in-memory template JSON, not the document. Authoring
gets a lightweight local undo (its own small command list scoped to `pnlTemplate`) so undoing a
"assign type" gesture doesn't pop a document payload edit. Two stacks, clear boundary: document edits
→ `IffEditController`; template-shape edits → the builder-local stack.

## Spacing Scale (WinForms — fixed strip heights & gaps)

Web px tokens do not apply. The contract reuses the **exact strip dimensions and gaps already in
`FormIffEditor.Designer.cs`** so the new pane is visually indistinguishable from the host:

| Token | Value | Usage (verbatim from existing Designer) |
|-------|-------|------------------------------------------|
| separator | 4px | `sep1`/`sep2` toolbar gaps; `SplitterWidth = 4` on both split containers |
| status/header strip | 22px | `pnlStatus`, `pnlLeafHeader`, and the new `pnlTemplateStatus` are all Dock height 22 |
| toolbar strip | 28px | `toolbar` height (unchanged; no new toolbar buttons this phase) |
| strip inset padding | 3px | `pnlStatus.Padding = (3,3,3,3)` — `pnlTemplateStatus` matches |
| toggle button width | 50px | `btnHexMode`/`btnTextMode`; new `btnTemplateMode` matches |
| Panel1 min size | 240px | left tree pane min (`Panel1MinSize`) — unchanged |
| Panel2 min size | 420px | right editor pane min (`Panel2MinSize`) — unchanged |
| field-row height | system default (`AutoScaleMode.Font`) | decoded field rows; do NOT hard-code a px row height — let DPI scale it |

Exceptions: monospace surfaces (raw-byte grid, hex cells, decoded scalar values) use Consolas 9pt
column metrics, not strip spacing. No 8-point web scale — this is a native desktop pane.

## Typography (WinForms)

Two font roles only, matching the host verbatim. No web sizes/weights/line-heights.

| Role | Font | Where |
|------|------|-------|
| UI chrome (labels, buttons, menu items, field NAMES, type names) | System default via `AutoScaleMode.Font` (≈8.25pt Segoe UI / MS Sans on the 6×13 base), `Colors.Font()` = `WhiteSmoke` | `pnlTemplateStatus` text, `btnTemplateMode`, FieldRecord name column, context-menu items, the multi-match picker |
| Byte / value (monospace) | **Consolas 9pt** (`new Font("Consolas", 9F)`) — identical to `txtHex` | the raw-byte hex grid, decoded scalar VALUES, offset/length columns, enum-map raw `value(name)` rendering |

Rule: anything that represents on-wire bytes or a numeric field value renders in Consolas 9pt so
columns align and a modder can eyeball byte boundaries. Anything that is a human label renders in the
chrome font. This split already exists in the host (Consolas hex pane, default-font header/status).

## Color (WinForms theme accessors — NOT web 60/30/10)

All colors come from `UtinniCoreDotNet.UI.Theme.Colors.*()`. Raw ARGB literals are banned by the
existing convention. **The dark theme palette has NO green token**, and the round-trip indicator
(D-07) needs a clearly-distinct "fits" state. Therefore this spec **sanctions exactly one new direct
color** following the precedent already set by `Color.Red` for errors.

| Role | Accessor / value | Usage (specific elements only) |
|------|------------------|--------------------------------|
| Dominant surface | `Colors.Primary()` = `(40,40,40)` | all panel backgrounds: `pnlTemplate`, `pnlTemplateStatus`, both split panels |
| Inset / data surface | `Colors.PrimaryHighlight()` = `(64,64,64)` | the raw-byte hex grid background, the field-list background (matches `txtHex`/`tvChunks`) |
| Default text | `Colors.Font()` = `WhiteSmoke` | field names, type names, byte values, status text |
| Disabled / secondary text | `Colors.FontDisabled()` = `(100,100,100)` | the **un-annotated raw-byte gutter** label, placeholder prompts, the leaf-header sub-caption |
| Accent (blue) | `Colors.Secondary()` = `(0,122,204)` | RESERVED FOR: (a) the **currently-selected byte span** highlight in the raw-byte grid; (b) the dirty `●` marker (existing); (c) the active-mode toggle button outline. Nothing else. |
| Control border | `Colors.ControlBorder()` = `(100,100,100)` | field-row separators, the annotated-span box outline |
| Status — fits (NEW) | `Color.FromArgb(78, 201, 76)` (VS-style status green) — **the one new sanctioned direct color** | the round-trip indicator strip text/glyph when **consumes-exactly + plausible** (D-07 green) |
| Status — does-not-fit / error | `Color.Red` (existing sanctioned exception) | round-trip indicator when key-matches-but-bytes-don't-round-trip (D-07 flagged); all validation/error copy in `pnlTemplateStatus` |

Accent reserved for: **selected byte span, dirty marker, active-mode outline** — never applied to
all-interactive-elements, never to the field rows wholesale.

**Un-annotated (raw, un-consumed) bytes — the candor-critical rendering (D-02):** bytes NOT yet
covered by a FieldRecord render in the **default `Colors.Font()` on `PrimaryHighlight()` background**
(i.e. they look like the existing plain hex dump), while **annotated** spans get a 1px
`ControlBorder()` box + a faint tint and a label tag. The contrast makes "you haven't consumed the
whole payload" impossible to miss: any plain, un-boxed run of hex at the tail is visibly unclaimed.
The `pnlTemplateStatus` strip additionally states `N of M bytes consumed` in words (see States).

## Copywriting Contract

All copy lands in `pnlTemplateStatus.lblTemplateStatus`, the `pnlLeafHeader.lblLeafHeader` caption,
context-menu item text, dialog captions, or the multi-match picker. Tone matches the host's candid,
specific voice ("Hex must be pairs of 0-9 / A-F. Remove the highlighted characters.").

| Element | Copy |
|---------|------|
| Primary CTA (the core gesture) | Context-menu item on a byte selection: **"Assign type & name…"** (opens the field-assign popup). Mirrors the existing `"Replace bytes from file…"` ellipsis idiom. |
| Mode toggle button | **"Template"** (50px, `btnTemplateMode`) |
| Empty state — no template, leaf is raw | Header caption: **"No template for this chunk. Select bytes and assign a type to start one."** in `Colors.FontDisabled()`. The raw bytes show below, fully un-annotated. |
| Empty state — leaf claimed by a built-in | `btnTemplateMode` hidden / disabled with tooltip: **"This file is decoded by a built-in editor — templates apply only to chunks Utinni doesn't recognize."** (states D-05 altitude plainly) |
| Round-trip indicator — fits (green) | **"Round-trip OK · {M} of {M} bytes consumed"** (green) |
| Round-trip indicator — partial | **"{N} of {M} bytes consumed — {R} bytes still raw"** (`FontDisabled()` while authoring; not an error, just incomplete) |
| Round-trip indicator — does NOT fit (flagged, D-07) | **"Template doesn't fit these bytes — decode stopped at offset 0x{off}. Showing raw."** (`Color.Red`) |
| Field-assign popup title | **"Assign field"** (a small modal: Name textbox, Type drop-down, optional repeat-spec, optional enum/flags map, encoding) |
| Error — bad field width / overrun | **"This type needs {k} bytes but only {r} remain in the chunk. Pick a smaller type or extend the field."** |
| Error — count-field references unknown field | **"The array count points at a field named '{x}' that isn't in this template yet. Define it before the array."** |
| Length-changing edit feedback | After a value edit that resizes the payload: status shows **"Edit applied · payload {old}→{new} bytes · count field recomputed."** (surfaces the D-10 auto-recompute so it's visible, not silent) |
| Save template | Pack-target menu item: **"Save template to pack…"** → sub-items per scanned dir (D-12): **"User templates"**, **"Project pack ({name})"**; shipped pack is read-only and shown disabled: **"Shipped (read-only)"** |
| Import / export pack | **"Import template pack…"** / **"Export this template…"** (file-dialog driven, mirrors `OpenFileDialog`/`SaveFileDialog` usage already in the host) |
| Multi-match tie picker (D-07) | Title **"More than one template matches"**; body **"{N} templates claim {TAG} under {path}. Pick one to apply:"** + a list (most-specific key pre-selected); buttons **"Apply"** / **"Cancel"** |
| Destructive — overwrite an existing template | Confirm via `FormSaveConfirmDialog` (the existing dialog): heading **"Overwrite '{name}' in {pack}?"**, body **"A template with this match key already exists in this pack. Overwriting replaces its field definitions."**, accept verb **"Overwrite"**, cancel **"Cancel"** |
| Destructive — delete a template | heading **"Delete template '{name}'?"**, body **"This removes the JSON file from {pack}. Chunks it auto-applied to will fall back to raw hex."**, accept verb **"Delete"**, cancel **"Cancel"** |

**Destructive actions inventory:** (1) overwrite an existing template in a pack, (2) delete a
template from a pack. Both route through the existing `FormSaveConfirmDialog` (heading/body/accept/
cancel verbs, body emphasis in `Color.Red`) — no new confirm widget. Applying a template to a chunk
and editing field values are NON-destructive (undoable via `IffEditController`; nothing written to
disk until an explicit Save▾, which reuses the existing provenance-gated Save matrix unchanged).

## Interaction Contracts (the heart of the phase)

### 1. The select → assign gesture (D-02)

1. User is in **Template mode** on a raw leaf. The raw bytes render in the top `splitTemplate.Panel1`
   as a monospace hex grid (offset col, hex pairs, ASCII gutter — reuse the `HexDump` format).
2. User selects a byte range (click-drag across hex cells). The selection highlights in
   `Colors.Secondary()` (blue). Offsets are **selections, not arithmetic** — the user never types an
   offset (D-02).
3. Right-click → **"Assign type & name…"** (the primary CTA) opens the field-assign popup.
4. On accept: a new `FieldRecord` appends to the template (in template field order = file byte
   order), the selected span gets a `ControlBorder()` box + tag label in Panel1, a typed row appears
   in the bottom field list (Panel2), the live decode + `FitReport` re-runs, and the indicator strip
   updates. The template JSON grows (the same D-01 artifact).
5. Un-annotated bytes remain plain/un-boxed — visibly raw — until consumed.

### 2. Field-list editing affordances (Panel2)

A list of typed rows (one per `FieldRecord`), each showing **name · type · decoded value · span**.
Row-level affordances (context menu + small inline buttons, matching the host's `UtinniButton` idiom):
- **Add / Remove / Reorder** (move up / move down) typed rows — mirrors the existing tree
  structural-op menu verbs (`Move up` / `Move down` / `Remove`) so the muscle memory transfers.
- **Edit value** inline (commit on Leave/Validating, never per-keystroke) — drives the document edit
  via `IffEditController` and re-runs the round-trip check.
- **Attach enum / flags map** (D-11): on an int field, a small editor for `name=value` (enum, label→
  literal) OR `name=bit` (flags, label→`1<<(bit-1)`, rendered OR'd as `walk|run`). The two
  conventions are EXPLICITLY distinct in the UI (a radio: "Enum (one value)" vs "Flags (combinable)")
  — Pitfall 4: a flags entry is a bit POSITION 1..32, not a mask.
- **Repeat-spec** (D-10), on a field declared as an array, a small chooser with three kinds:
  **"Fixed count"** (integer), **"Count from field…"** (drop-down of prior int fields — the encoder
  auto-recomputes this on write), **"Until end of chunk"** (trailing remainder). Sentinel-terminated
  is NOT offered this phase (deferred).
- **Widen match key** (D-04): a toggle on the template header — **"Match: {TAG} under {path}"** vs
  **"Match: any {TAG}"** — captured from the tree position at authoring time, author-widenable to
  tag-only. Version-FORM stays in the path (REQUIRED — CLEF CPAP 3-layout case).

### 3. Auto-apply surfacing (D-05 / D-07)

- On selecting a leaf that has no built-in and a template matches with a **green** FitReport, the pane
  opens in Template mode automatically, indicator green, no prompt (silent auto-apply). The user can
  still toggle to Hex/Text.
- On a key-match whose bytes do NOT round-trip, the pane opens in Template mode but shows the raw
  bytes with the **"Template doesn't fit these bytes…"** red flag (D-07) — the decode is shown as far
  as it got, the rest stays raw. Never silently mis-decodes.
- On a **genuine multi-match tie**, show the small picker (Interaction copy above); most-specific key
  is pre-selected; the picker is a modal `UtinniForm`-style dialog, list + Apply/Cancel.

### 4. Candor states (always visible, never hidden)

| State | Visual |
|-------|--------|
| Fully consumed, plausible | green strip "Round-trip OK · M of M bytes consumed"; all bytes boxed/tagged |
| Partially annotated (authoring) | neutral strip "N of M consumed — R bytes still raw"; tail bytes plain/un-boxed |
| Annotated but doesn't round-trip | red strip "Template doesn't fit these bytes — decode stopped at 0x{off}"; raw shown |
| Length-changing edit | strip "payload {old}→{new} bytes · count field recomputed" then settles to the consumed-count line |
| Built-in claims the file | Template toggle disabled with the altitude tooltip; no template engages |
