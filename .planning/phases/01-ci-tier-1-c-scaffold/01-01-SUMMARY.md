- **Found during:** Task 2 verification (Step d - msbuild invocation)
- **Issue:** `msbuild Utinni.sln /restore /p:Configuration=Release /p:Platform=x86 /m` fails with two pre-existing errors:

This is a pre-existing sln/csproj mismatch that exists in the main repo before any changes from this plan.

- **Root cause:** The plan's `truths` assumed a fully functional local VS 2019 + MSVC v142 build environment where the CON-T-01 chain has already run to produce a fresh `Generated/UtinniCore.cs`. The executor agent environment has the same error in the original repo (verified: msbuild fails identically against `D:/Code/Utinni/Utinni.sln` without any of our changes).
- **Fix:** NOT applied (pre-existing, out of scope per STAB-04 preservation + "no refactor of CON-T-01 chain"). The first CI run (Plan 02) on `windows-2022` will have the full MSVC v142 build environment and the CON-T-01 chain will regenerate `UtinniCore.cs` during the build.
- **Alternative verification:** `dotnet restore UtinniCoreDotNet.Tests/UtinniCoreDotNet.Tests.csproj --use-lock-file` succeeded (exit 0), confirming NuGet packages resolve correctly and `packages.lock.json` was generated.
- **Impact:** The `msbuild` + `dotnet test` round-trip local verification could not be completed in the executor environment. Plan 02 (CI workflow) will provide the authoritative green/red signal.
