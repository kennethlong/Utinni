<objective>
Add the highest-risk save mode (D-05.4): a framework-side `TreWriter` that repacks a `.tre` archive by
full rebuild, plus the editor wiring behind a confirm dialog with an opt-in TIMESTAMPED backup and a
locked-archive fallback. Per 08-REVIEWS HIGH-1 the byte-identity claim is rewritten: untouched entries
are guaranteed under TWO distinct properties — (a) **logical payload identity** (GetRecordData equality)
AND (b) **raw compressed slice preservation** (verbatim bytes at [rec.Offset, rec.Offset+rec.CompressedSize)
copied from the source archive). Only the edited entry recompresses. The new `GetRecordCompressedBytes`
API on `TreFile` makes (b) achievable; the original "untouched entries are byte-identical to the original
archive bytes" full-file claim is dropped as misleading.

The repack menu is provenance-gated per 08-REVIEWS HIGH-2: enabled only when `FormIffEditor.Source is
OpenSource.TreArchive ta`. 08-05 populates this from the TRE Browser hand-off. This resolves the
logical-path-only handoff gap.

Backups are TIMESTAMPED per 08-REVIEWS MEDIUM-10 (`<name>.tre.<yyyyMMdd-HHmmss>.bak`) so a failed second
attempt cannot destroy the prior known-good backup. Atomic replace is via `File.Replace` to a temp
sibling on the same volume; on failure (likely cause: client holds the archive open while injected), the
UI falls back to "Save loose override of edited entry only" — no partial-write.

Purpose: D-05.4 is a hard V1 must-have (closest to edit-in-place). SWG does NOT support in-place `.tre`
patching (swg-client-v2 reference); the only sanctioned model is loose override (08-05) or full rebuild
(this plan).

Output: `TreFile.GetRecordCompressedBytes` + its unit suite, `TreWriter.cs` (framework) + the two-
guarantee repack test, and `TreRepackSaveTarget.cs` + `Save ▾` wiring + live smoke (UtinniPlugins repo).
