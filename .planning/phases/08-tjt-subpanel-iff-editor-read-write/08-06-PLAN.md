<objective>
Add the isolated, higher-risk in-memory live-patch save mode (D-05.3): write the loaded IFF's edited
bytes straight into mapped client memory via the CON-N-04 `Memory.memory.Copy` VirtualProtect bracket
on the game thread, behind a risk-proportional confirm dialog AND gated on
`FormIffEditor.Source is OpenSource.ClientMemory` (08-REVIEWS HIGH-2). V1 enforces SAME-LENGTH-ONLY
patches (08-REVIEWS HIGH-3) — refusing both growth AND shrink closes the stale-tail-bytes corruption
vector and is the simplest defensible V1 constraint per Codex/Cursor consensus. This is the 8b isolated
plan — it touches live client memory and is validated by live-SWG smoke only.

Purpose: D-05.3 is a hard V1 must-have (instant in-session feedback; volatile, lost on reload). It is
isolated per the D-05 PLAN-SPLIT FLAG because the mapped-memory write carries distinct failure modes
(AV / device-lost / client crash) from the file save modes.

**Note on phase scope:** No current Phase-8 open path constructs `OpenSource.ClientMemory` (acknowledged
in 08-01 Task 3 + 08-REVIEWS HIGH-2(b)). The implementation is COMPLETE and unit-testable for its bounds
gate, but the menu remains DISABLED in this phase until a follow-up phase wires a discovery path. The
phase is otherwise satisfied at the implementation-ready level for D-05.3.

Output: `LivePatchSaveTarget.cs`, `FormSaveConfirmDialog.cs`/`.Designer.cs`, the `Save ▾` wiring +
provenance gate in `FormIffEditor`, and a live-SWG smoke checkpoint that is currently exercised only
