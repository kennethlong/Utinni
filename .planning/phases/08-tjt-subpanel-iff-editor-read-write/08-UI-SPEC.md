# Phase 8 — UI Design Contract: TJT IFF Editor (read + write)

> Visual and interaction contract for the foundational Wave-1 read/write editor: a chunk-level
> IFF editor (editable hex / inline text / replace-from-file leaf payloads + add/remove/
> rename-retag/reorder/duplicate structural tree ops), editor-local undo/redo, four save modes
> (loose-override / Save·Save-As / in-memory live patch / `.tre` repack), and an editor-forced
> in-session client reload. Shipped inside The Jawa Toolbox (DEC-C4).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **PLATFORM: .NET Framework 4.7.2 WinForms desktop UI — NOT web/CSS.** No component library,
> no shadcn, no Tailwind, no icon font. The "design system" is the existing Utinni themed
> WinForms control suite (`UtinniCoreDotNet.UI`). Every token below is extracted from real code
> (`Colors.cs`, `UtinniForm.cs`, the themed controls, `TreDetailPane.cs`) — none invented.
>
> **THIS SPEC EXTENDS `07-UI-SPEC.md` — it does not re-derive it.** Phase 7's design system,
> spacing scale, typography, color contract, and host-placement rule (Wave-1 editors ship as
> resizable `UtinniForm` windows, NOT 417px SubPanels) are treated as LOCKED and inherited
> verbatim. The sections below restate the locked tokens for the checker's six dimensions and
> then specify ONLY the new/changed surfaces Phase 8 adds: edit affordances, dirty/validation
> states, the structural-op + FourCC-tag UX, undo/redo, the save-target chooser, and the forced
> reload affordance.

## Host Placement Decision

**DECISION: Ship the IFF Editor as a NEW resizable `UtinniForm` (`FormIffEditor`), registered in
the plugin's `GetForms()` list — exactly per the Phase 7 precedent rule.** The TRE Browser
(`FormTreBrowser`) STAYS read-only and is a separate window; it gains only an "Open in IFF Editor"
hand-off entry point (D-09).

| Property | Value |
|----------|-------|
| Host type | `UtinniForm` (resizable, custom titlebar, `DrawName = true`, TJT icon — mirrors `FormTreBrowser`) |
| Window title | `IFF Editor` — with an unsaved-changes marker and filename suffix (see Dirty State) |
| Default size | 1100 × 760 (persist `[IffEditor] width/height` to settings.ini, mirroring `FormTreBrowser`'s ini pattern) |
| Minimum size | 820 × 560 (below this the tree + hex + structural toolbar are unusable) |
| Open behavior | "Already open? `Activate()` : `Show()`" guard, identical to `FormTreBrowser.Create()` — BUT see multi-document note |
| Multi-document | V1 default: **single document per window** (open-replaces with a dirty-prompt). The "already open → Activate" guard applies; opening a second file prompts to save/discard the current one. (Tabbed MDI is out of scope; deferred.) |

**MEF SPI conformance (CON-M-01/02):** the new Form returns from `GetForms()`; `GetSubPanels()`
stays as-is; the interface is NOT widened (preserve the foundation per STAB-04). The shared
chunk-tree control extracted from `TreDetailPane` (D-09) is a `UserControl` consumed by both
`FormTreBrowser` (read-only) and `FormIffEditor` (editable) — extraction must not change
`TreDetailPane`'s public read API consumed by Phase 7.

**Fallback if the Form path is blocked in execution:** degrade to a `StandalonePanel` (dockable
UserControl) at no less than 900×620; never the fixed 417px SubPanel. (Same fallback as Phase 7.)

## Layout Contract (WinForms)

### Window regions (top → bottom)

`FormIffEditor` client area, docked top-to-bottom:

1. **Editor toolbar** (`Dock = Top`, height 28px) — left-to-right:
   `Open…` · `Save ▾` (drop-down: the 4 save modes) · separator · `Undo` · `Redo` · separator ·
   `Reload in client` · (right-aligned) a **dirty-state label** (`UtinniLabel`).
   - Toolbar background `Colors.Primary()`; buttons are `UtinniButton` (accent face) or themed
     `ToolStrip` buttons; disabled buttons render `Colors.FontDisabled()`.

2. **Two-region split** (`SplitContainer`, `Orientation = Vertical`, `BackColor = Colors.Primary()`,
   `SplitterWidth = 4`) filling the remaining area:

   | Region | Side | Default width | Min width | Resize |
   |--------|------|---------------|-----------|--------|
   | Chunk tree (editable structure) | Left (`Panel1`) | 360px | 240px | user-draggable; persist `SplitterDistance` to ini |
   | Leaf editor pane | Right (`Panel2`) | remaining | 420px | fills |

3. **Status strip** (`Dock = Bottom`, inset 3px) — a `UtinniLabel` for the active operation /
   validation result (mirrors `FormTreBrowser`'s inset status panel). Not modal.

### Left region — editable chunk tree

- Reuses the **shared chunk-tree control extracted from `TreDetailPane.tvChunks`/`LoadIff`** (D-09).
  Same theming as Phase 7: `BackColor = Colors.PrimaryHighlight()`, `ForeColor = Colors.Font()`,
  `BorderStyle = None`, `HideSelection = false`, `ShowLines = true`.
- Each node label keeps the Phase 7 format `TAG [SubType]  ·  N bytes  ·  @offset`.
- **Right-click context menu (`UtinniContextMenuStrip`) — structural ops (D-03):**
  `Add chunk…` · `Add FORM…` · `Remove` · `Rename / retag…` · `Edit FORM sub-type…` ·
  `Duplicate` · `Move up` · `Move down`. Items disable contextually (e.g. `Edit FORM sub-type`
  only on a FORM container; `Move up` disabled on the first sibling).
- **Dirty markers (see Dirty State below)** render inline on the node.

### Right region — leaf editor pane

Populated on tree `AfterSelect` of a **leaf** chunk. Top-to-bottom:

1. **Leaf header strip** (`Dock = Top`, ~22px): the leaf's `TAG · N bytes` + an **edit-mode toggle**
   (`Hex` / `Text`) shown only when the payload is ASCII-ish (D-04.3); for non-ASCII leaves only
   `Hex` is offered. A `read-only` vs `editable` cue (see States).
2. **Editor surface** (`Dock = Fill`):
   - **Hex mode:** the existing `txtHex` `TextBox` (Consolas 9pt, `Colors.PrimaryHighlight()`),
     `ReadOnly = false`. Length may grow/shrink (D-04.1). Invalid hex input is flagged (see
     Validation State) — never silently dropped.
   - **Text mode:** a multiline `UtinniTextbox`, same surface color, for printable-ASCII payloads.
3. **Leaf context menu (`UtinniContextMenuStrip`)** on the editor surface (D-04.2):
   `Replace bytes from file…` · `Export bytes to file…`.

When a **container (FORM/LIST/CAT) node** is selected, the right region shows a read-only summary
(child count, sub-type, rolled-up length) — containers are edited structurally via the tree menu,
not byte-wise.

## States

| State | Trigger | UI |
|-------|---------|----|
| **Empty (no document)** | Editor opened with no file loaded | Tree empty; right pane centered dimmed `UtinniLabel` (`Colors.FontDisabled()`): heading `No IFF file open` + body `Open a file from the toolbar, or use "Open in IFF Editor" from the TRE Browser.` Save/Undo/Redo/Reload disabled. |
| **Loading** | File opening / payload reading on a background `Task` | Status strip: `Opening <name>…`. Window stays responsive (no modal spinner — WinForms convention, inherited from Phase 7). |
| **Read-only leaf (none-selected)** | Document open, a container selected or nothing selected | Right pane shows the container summary or the empty hint; hex/text surfaces hidden or read-only. |
| **Editable leaf (clean)** | A leaf selected, not yet edited | Hex/text surface editable (`ReadOnly = false`); leaf header shows an `Editable` cue at `Colors.Font()`. Border/affordance distinguishes it from the Phase 7 read-only hex (which used `ReadOnly = true`). |
| **Edited / dirty leaf** | User changed bytes/text in this leaf | The tree node label gets a leading dirty marker `● ` and renders at `Colors.Secondary()` accent color (the reserved accent — see Color). The window title gains a leading `●` and the toolbar dirty-label reads `Unsaved changes`. |
| **Added node** | User added a chunk/FORM | New node renders at `Colors.Secondary()` with a `＋` prefix until saved. |
| **Removed node** | User removed a chunk (before save) | Removal is immediate in the tree (with undo available); no tombstone row. The parent's rolled-up size updates. Undo restores it. |
| **Validation warning (pre-save)** | Serialize/round-trip check finds an issue (e.g. odd FourCC, non-hex chars, length mismatch) | Status strip turns its text to `Color.Red` with the specific problem + fix; the offending field/leaf is focused. Save is blocked until resolved OR the user explicitly proceeds via a confirm dialog (see Destructive). NEVER a silent corrupt-save. |
| **Save in progress** | A save mode is executing | Status strip: `Saving (<mode>)…`; toolbar disabled during the write. |
| **Save succeeded** | Write completed | Status strip (normal `Colors.Font()`): `Saved <name> (<mode>)`. Dirty markers cleared; title `●` removed. |
| **Save failed** | Write threw (IO, repack/CRC error, VirtualProtect failure) | Status strip `Color.Red`: `<reason>. Your edits are kept in the editor — try another save target.` Dirty state RETAINED (edits not lost). |
| **Reload triggered** | `Reload in client` invoked after a file-based save | Status strip: `Reloading in client…` then `Client reloaded` (or, if no reload hook is available, the D-06 fallback message — see Copywriting). |
| **Reload unavailable / no live client** | `!Game.IsRunning`, or no asset-reload hook resolvable (D-06 research item) | `Reload in client` button disabled with tooltip `No live client — start SWG to reload edits in-session.` (or, if a client is running but no hook exists, the documented fallback copy). |

## Color (inherited from Phase 7 — accent reserved-list extended)

Mapped from `UtinniCoreDotNet.UI.Theme.Colors` (fixed Dark theme). Pull via `Colors.*()`
accessors at runtime; the hex below documents what they return. NO raw `Color.FromArgb` literals.

| Role | Accessor | Value | Usage |
|------|----------|-------|-------|
| Dominant (~60%) | `Colors.Primary()` | #282828 (40,40,40) | Form background, toolbar, pane backgrounds, splitter |
| Secondary surface (~30%) | `Colors.PrimaryHighlight()` | #404040 (64,64,64) | Chunk tree background, editable hex/text surfaces, list backgrounds |
| Shadow / deep recess | `Colors.PrimaryShadow()` | #191919 (25,25,25) | ListView header band; dividers; pressed states |
| Accent (~10%) | `Colors.Secondary()` | #007ACC (0,122,204) | RESERVED — see list below |
| Foreground text | `Colors.Font()` | #F5F5F5 WhiteSmoke | All primary text; clean tree nodes; editable-leaf cue |
| Dimmed / disabled | `Colors.FontDisabled()` | #646464 (100,100,100) | Empty-state text; disabled toolbar buttons; metadata keys |
| Control border | `Colors.ControlBorder()` | #646464 (100,100,100) | 1px control outlines where drawn |
| Destructive / error | `Color.Red` (as `UtinniForm` close button uses) | #FF0000 | Validation-warning text; save-failure text; destructive-confirm emphasis ONLY |

**Accent (`#007ACC`) reserved for — explicit list (never "all interactive elements"):**
1. The 2px top accent rule on the window titlebar (inherited `UtinniForm.OnPaint`).
2. The 2px top accent rule on the type/version banner (inherited from `TreDetailPane`).
3. The selected tree node / selected list row highlight (system-selection styling).
4. The primary `Save` toolbar button face (`UtinniButton` already uses `Colors.Secondary()`).
5. **NEW: dirty/edited/added node indication** — edited or newly-added chunk-tree nodes render
   their label at `Colors.Secondary()` (with a `●`/`＋` text glyph) to mark unsaved change.

Accent is NOT used for: ordinary buttons' bodies beyond the existing `UtinniButton` face, borders,
section dividers, labels, the read-only-vs-editable leaf cue (that uses `Font()` vs `FontDisabled()`),
or validation errors (those use `Color.Red`).

**Destructive color (`Color.Red`)** flags: (a) validation/serialize warnings, (b) save failures,
(c) the emphasis text inside the remove/live-patch/repack confirmation dialogs. Unlike Phase 7,
Phase 8 DOES have destructive actions (see Copywriting) — but the destructive color marks the
warning/error, not every write button.

### Destructive / risky actions (each + confirmation approach)

Phase 8 has three risk-bearing actions. Confirmation is **proportional to risk** (per CONTEXT
guard-rails). Each confirm dialog is a small `UtinniForm` modal (like `FormHotkeyEditorDialog`)
with the warning text in `Color.Red` emphasis and explicit verb buttons (never bare `OK`/`Cancel`).

| Action | Risk | Confirmation |
|--------|------|--------------|
| **Remove chunk** | Local, fully undoable via editor-local undo (D-08) | **No modal.** Immediate; undoable. (A node-level remove is low-risk because nothing is written to disk/memory until a save mode runs.) |
| **Patch live client (in memory)** (D-05.3) | Writes mapped client memory via the CON-N-04 VirtualProtect bracket; volatile, lost on reload, can destabilize a live session | **Confirm dialog:** heading `Patch the live client in memory?` · body `This writes your edits straight into the running client. The change is temporary (lost on reload) and can destabilize the session. Continue?` · buttons `Patch live` / `Cancel`. |
| **Repack into source .tre** (D-05.4) | Full repack with CRC/TOC rebuild; rewrites a shared archive the client loads; highest blast radius | **Confirm dialog:** heading `Repack <archive>.tre?` · body `This rebuilds the archive's table of contents and CRCs and overwrites <archive>.tre. Other files in the archive are preserved byte-for-byte, but back up the archive first if you're unsure. Continue?` · buttons `Repack` / `Cancel`. Offer (planner discretion) a "back up the .tre first" checkbox defaulted on. |
| **Save anyway over a validation warning** | User overrides a serialize/round-trip warning | **Confirm dialog:** heading `Save despite the warning?` · body `<the specific warning>. Saving may produce a file the client can't read. Save anyway?` · buttons `Save anyway` / `Cancel`. |
| **Discard unsaved edits** (open-replace / window close while dirty) | Loses editor-local edits | **Confirm dialog:** heading `Discard unsaved changes?` · body `<name> has unsaved edits. Save before <opening another file / closing>?` · buttons `Save` / `Discard` / `Cancel`. |

## Accessibility / Interaction Notes (WinForms)

- **Keyboard:** TreeView arrow-key navigation + Enter native; editable hex/text surfaces take
  focus on leaf select. **Editor-local undo/redo bind to `Ctrl+Z` / `Ctrl+Y`** scoped to the
  editor (D-08) — these must NOT dispatch to the scene `UndoRedoManager`. Tab order:
  toolbar → tree → leaf editor.
- **Dirty-glyph + color, not glyph-alone:** dirty/added nodes use BOTH a text glyph (`●`/`＋`)
  and the accent color, so the state is legible without relying on color discrimination alone.
- **Thread marshaling (CON foundations):** file open/read/save and `.tre` repack run on a
  background `Task`; every UI mutation marshals via `Control.Invoke`/`BeginInvoke`
  (the `FormTreBrowser` precedent). The in-memory live patch (D-05.3) and forced reload (D-06)
  touch the live client and MUST run on the game thread via `GameCallbacks.AddMainLoopCall`,
  bracketing any mapped-memory write with `VirtualProtect` (CON-N-04) — never from the UI thread.
- **No modal blocking for progress:** loading/saving states are inline status-strip text, never
  modal dialogs. Modals are reserved for the risk confirmations + FourCC entry above.
- **Edits never silently lost:** a failed save RETAINS the editor's dirty state; closing/opening
  while dirty always routes through the discard-confirm dialog.
- **High-DPI:** inherit `AutoScaleMode.Font` from `UtinniForm`; no hard-coded pixel sizes that
  fight DPI scaling beyond the documented control metrics.

## Assumptions To Confirm (recorded, non-blocking)

Per the orchestrator's guidance, where CONTEXT + the Phase 7 baseline left a genuinely open UI
question, a reasonable assumption consistent with the Phase 7 baseline is recorded here rather
than blocking on interactive questioning:

1. **Single-document-per-window** (open-replaces with a dirty-prompt) for V1; tabbed/MDI multi-doc
   deferred. Rationale: matches the `FormTreBrowser` "already open → Activate" single-window guard;
   tabbed editing is net-new host infrastructure.
2. **Editable hex stays the existing `txtHex` hex+ASCII dump textbox made editable**, NOT a new
   purpose-built hex-grid control. Rationale: D-09 says reuse/extend the Phase 7 surface; a hex grid
   is a hand-rolled widget the "don't hand-roll" rule discourages for V1. Revisit if byte-accurate
   column editing proves unworkable in a plain textbox.
3. **`Reload in client` is a single toolbar button** whose enabled/disabled state + tooltip encode
   the D-06 research outcome (direct hook vs scene-change fallback vs unavailable). The exact reload
   mechanism is a D-06 RESEARCH item for the planner; the UI contract only fixes the affordance,
   its states, and its copy.
4. **Save-target chooser is a `Save ▾` split/drop-down button**, not four separate toolbar buttons.
   Rationale: keeps the toolbar compact and makes the destination explicit at the moment of saving
   (where the risk copy + confirm live).
5. **`.tre` repack offers an opt-in "back up the archive first" checkbox** (defaulted on) in its
   confirm dialog. Rationale: proportional-to-risk guard-rail; planner may drop it if the repack
   path is made atomic/transactional instead.

These do not change locked decisions; flag any disagreement at planning time.
