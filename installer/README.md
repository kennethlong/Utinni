# Utinni MSI Installer (WiX 5)

This directory builds `Utinni.msi`, the Windows installer for Utinni (D-20). It is
a WiX 5 SDK-style project plus a managed (DTF) custom action that implements the
**opt-in, default-OFF** SWG client path detector (D-20 / D-21, preserving the
CON-D-01 ships-blank policy).

## Layout

| File | Purpose |
|------|---------|
| `Utinni.Installer.wixproj` | WiX 5 SDK project (`WixToolset.Sdk/5.0.2`). Produces `bin/x86/Release/Utinni.msi`. |
| `Product.wxs` | Package definition: install dir, components, Start Menu shortcut, opt-in dialog, custom-action wiring. |
| `License.rtf` | MIT license shown in the WixUI license dialog. |
| `CustomActions/SwgPathDetector.csproj` | Managed custom action project (`WixToolset.Dtf.CustomAction/5.0.2`, net472). |
| `CustomActions/SwgPathDetector.cs` | The opt-in detector (registry + filesystem probe; writes `ut.ini` only on a single unambiguous match). |

## Pinned versions

- **WiX SDK:** `WixToolset.Sdk` **5.0.2** (latest stable as of 2026-05-25).
- **WiX UI extension:** `WixToolset.UI.wixext` **5.0.2**.
- **DTF custom action SDK:** `WixToolset.Dtf.CustomAction` **5.0.2** (pulls in `WixToolset.Dtf.WindowsInstaller`).

## Upgrade / version strategy

- **UpgradeCode (STABLE, never change):** `C4CC96BC-A1B4-4BD8-99D6-EF2CA3877D1D`.
  This GUID is the identity of the Utinni product family across all versions. A
  fork that changes it breaks the in-place upgrade path. It is declared once in
  `Product.wxs` `<Package UpgradeCode="...">`.
- **ProductCode (per-release):** auto-generated by WiX every time `Version`
  changes (the default WiX behaviour — `ProductCode` is omitted from `<Package>`).
  Combined with `<MajorUpgrade>`, this gives clean in-place upgrades for future
  `v1.0.x` releases: installing a newer MSI removes the older one first.

## Install behaviour

- Install path: `C:\Program Files (x86)\Utinni\` (`ProgramFiles6432Folder`, x86
  package per CON-P-02).
- Payload: `Launcher.exe`, `UtinniCore.dll`, `UtinniCoreDotNet.dll`,
  `UtinniCore-Symbols.dll`, `ut.ini`, `utinni.cfg`, `input.ini`, `licenses.txt`,
  and `Icons\`. **TheJawaToolbox** is bundled under `Plugins\TheJawaToolbox\`
  **only in the release.yml build** (see below).
  - **Deviation from the plan file list:** `UtINI.dll` is NOT bundled — UtINI is a
    static library (`bin/Release` ships `UtINI.lib` only), linked into
    UtinniCore/Launcher. There is no DLL to install.
- Start Menu: "Utinni" shortcut to `Launcher.exe` + an "Uninstall Utinni" shortcut.
- Opt-in SWG detection: a default-UNCHECKED checkbox ("Detect SWG client path and
  seed utinni.cfg"). When ticked, the deferred `DetectSwgPath` custom action probes
  common SWGEmu locations + registry and seeds `[Launcher]swgClientPath` in `ut.ini`
  **only if exactly one client is found**. Zero or multiple matches leave `ut.ini`
  blank (CON-D-01). Detection never fails the install (`Return="ignore"`).

## Build

Prereq: build the solution `Release|x86` first so `bin/Release/` is populated:

```pwsh
msbuild Utinni.sln /m /restore /p:Configuration=Release /p:Platform=x86
dotnet build installer/Utinni.Installer.wixproj -c Release
```

Output: `installer/bin/x86/Release/Utinni.msi` (the WiX SDK routes output through the
`$(Platform)` dir; the x86 package per CON-P-02 lands under `bin/x86/Release`).

### TheJawaToolbox payload (release builds only)

Local builds omit TJT. The `release.yml` workflow checks out
`kennethlong/UtinniPlugins` at a pinned SHA (see
`../.planning/phases/06-cleanups-dep-bumps-open-questions-tier-4-doc-1-0-cut/06-06-MSI-TJT-PINNING.md`),
builds TheJawaToolbox, stages its DLLs into
`installer/Payload/Plugins/TheJawaToolbox/`, and builds the MSI with the
`IncludeTjt` preprocessor constant defined:

```pwsh
dotnet build installer/Utinni.Installer.wixproj -c Release -p:DefineConstants=IncludeTjt
```

## Test on a clean VM (Tier-4 scenario, 06-06 Task 4)

1. Spin up a clean Windows 10/11 VM (Hyper-V / VirtualBox / VMware).
2. Copy `Utinni.msi` to the VM (shared folder or HTTP).
3. Run it; accept the SmartScreen warning (unsigned — D-23).
4. Verify `C:\Program Files (x86)\Utinni\` is populated and `ut.ini` ships blank.
5. Verify the Start Menu "Utinni" shortcut launches `Launcher.exe`.
6. Test BOTH detection paths: opt-out (default; `ut.ini` stays blank) and opt-in
   (with a known SWG install on the VM; `ut.ini` is seeded).
7. Uninstall via Settings → Apps; verify the install folder + `HKCU\Software\Utinni`
   are removed. Reinstall to confirm a clean round-trip (no "files in use").

The MSI is **unsigned** for V1 (D-23); SmartScreen warns on first run. Authenticode
signing is deferred to V2.
